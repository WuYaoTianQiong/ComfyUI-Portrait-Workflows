### Flux 结论

1. **Flux 必须用英文**：中文原始长提示词直接生成了完全无关的街景；这不是 seed 问题，是文本编码器/training 语言问题。Flux 的英文长提示词理解很好，中文必须先翻译。

## 实测结论

1. **Krea2 不是不会画身材**：短版/压缩版提示词都能画出“毛衣被超巨大乳房撑起”的效果；长版原提示词在同样参数下几乎不生效。瓶颈是长提示词里的服饰/镜头/面部约束把身材 token 稀释了，不是模型完全没这个能力。
2. **ZIT 对长提示词的容纳能力更强**：原始长版就能画出衣服下的胸部轮廓；身材+服饰合并后更明显，且制服细节完整。这符合它 17 步 CFG3 + 双程 + LoRA 的配置。
3. **CFG2 在这两个 Krea2 加速模型上不可用**：V8SE 直接全黑，V25 严重花屏。之前“试 CFG 2–3”的建议被实测否定；这两条线应保持 CFG1。
4. **加步数 12/CFG1 不解决身材问题**：V8SE_F、V25_D 没有黑图/花屏，但身材仍不生效。步数不是主要矛盾。
5. **降分辨率只解决速度，不解决理解**：1MP 比 2.16/2.4MP 快 3–4 倍，但长提示词的身材仍不生效；适合做草稿。
6. **压缩版提示词是 Krea2 的可用折中**：保留“身材+制服”关键关系，去掉大量镜头/条件句，能在 20–23s 内同时画出身材和制服，代价是毛衣下摆轻微结构错误。
7. **bypass 修复有效**：所有 Krea2 实验都走修复后的单程链路，第二程不再偷偷执行。
8. **ZIT 原版缺 `base_name`**：当前 `ResolutionPresetPicker` 必填，atelier 直接提交会 400；已在 `workflow_parser` 里按 `object_info` 默认值补齐，原版 ZIT 现在可直接通过 API 提交，输出与手工补字段的副本像素级一致。

## 建议

- 这条长提示词：**用 ZIT + 合并版提示词**。
- 需要 Krea2 的速度：用 **1MP、8 步、CFG1、压缩版提示词**；不要用 CFG2，也不要指望加步数解决身材。
- 如果必须用原始长提示词：ZIT 是更合适的工具；Krea2 只能保证制服/构图，不保证身材。

## 分辨率实测：原生 1.0× 最稳，1.25×–1.5× 是直出甜点

> 2026-11-01 重测（比例契约接入后）。固定 seed=123456789、同一段古风全身提示词（取自 `Qwen21_NSFW_t2i_atelier_1793539685174_6539` 的元数据），Qwen 2.1 25 步、NSFW LoRA 0.8，10/10 success。尺寸由「比例 + 目标 MP」算出（原生 1.012MP × 倍率²，对齐 16 的倍数），**不再是「基准宽高 × 倍率」**，所以尺寸随比例变化。

| 档位（UI 文案） | 2:3 实际尺寸 | 9:16 实际尺寸 | 目标 MP | 耗时（2:3 / 9:16） | 结果 |
|---|---|---|---:|---:|---|
| 0.75× | 608×928 | 560×1008 | 0.57 | 6.4s / 7.8s | 低于原生，偏软，不建议定稿 |
| 原生 1.0× | **832×1216** | 752×1344 | 1.01 | 10.5s / 11.0s | **Qwen 原生 1MP**，构图/解剖最稳 |
| 1.25× | 1024×1536 | 944×1680 | 1.58 | 17.3s / 17.9s | 细节明显更实，**直出甜点** |
| 1.5× | 1232×1840 | 1136×2016 | 2.28 | 26.5s / 26.9s | 细节继续增加，画幅开始变宽 |
| 2.0× | 1648×2464 | 1504×2688 | 4.05 | 54.5s / 54.3s | 画幅明显变宽，约 5× 耗时，收益递减 |

说明：

1. 耗时是模型已加载、每个尺寸首次跑的真实值；尺寸/seed/prompt 完全相同再次提交会命中 ComfyUI 执行缓存（约 1s）。
2. Qwen-Image 2.1 的训练/原生分辨率约 1MP，832×1216 是它的舒适区。**但「原生」不等于画质上限**：往上加分辨率会换来更实的纹理，代价是耗时按 token 数增长。
3. **固定 seed 不等于固定构图，而且构图随尺寸不是单调变化的**：latent 形状变了，噪声场就变了。同一 prompt/seed 实测：832×1216 与 1024×1536 是半身，1232×1840 收紧成近景，1648×2464 又拉回更完整的全身。需要特定景别时，用提示词锁定（full body / 脚不入画）或先实测一档，别假设"越高越完整"。
4. 2.0× 本次 10 张样本没有出现明显解剖错误，但耗时约 5×、构图漂移明显；"4MP 解剖风险"是统计性风险，不是每张必崩。
5. 比例本身几乎不影响耗时：同为 1.58MP 的 2:3（1024×1536）与 9:16（944×1680）只差 0.6s，**token 数才是主因**。
6. **要真正的大图/更清晰，推荐 1.0× 或 1.25× 直出后走 SeedVR2 超分**（仓库已有 `图片超分_SeedVR2_7B_源图命名_最高4K实测.json`），比 2.0× 直出更稳，也更容易保持同一张脸和姿势。
