## §2 决定性实测证据

### 2.1 ComfyUI 节点层面的"与 / 或"

| 节点 | 输入 | 必填性 | 结论 |
| --- | --- | --- | --- |
| `TextEncodeQwenImage21` | `images` = `COMFY_AUTOGROW_V3`，`names: image_1…image_16`，**`min: 0`** | 可增删 | **0–16 张任意组合** |
| `TextEncodeQwenImageEditPlus` | `image1` / `image2` / `image3` | 三者**均为 optional** | 1–3 张任意组合 |
| `LoadImage` | `image` | **required** | 每个 LoadImage 必须喂图 |
| `EmptyFlux2LatentImage` | `width` / `height` / `batch_size` | **全部 required** | 尺寸可直接指定 |
| `GetImageSize` | `image` | required | 用于"跟随输入图" |

**结论：不是"全都是与"，而是分两类——**

- **Qwen 系（Qwen21 / QwenEdit）：原生支持"或"**。三槽可任意空白，靠 `images` 的 autogrow / `image1-3` 的 optional 实现，**不需要改造工作流**。
- **Flux 系（PornMaster）：是"与"**。`LoadImage.image` 必填，少喂一张即缺输入；降级只能**换工作流**（双图换衣 / 单图编辑）。

### 2.2 10 个 studio 工作流的输入能力

| 工作流 | 图输入 | 尺寸机制 | 可少喂？ |
| --- | ---: | --- | --- |
| Qwen21+VNCCS 三图 25步 单人 | 3 | `resolution=1024`（参考图缩放），输出跟随参考图 | **是（0–16）** |
| QwenEdit GGUF-Q5KM 三图 4步（标准 / 全身 / 自动裁切） | 3 | 无 resolution，输出跟随参考图 | **是（1–3）** |
| QwenEdit Nunchaku-fp4 三图 4步 低显存 | 3 | 同上 | **是（1–3）** |
| PornMaster 三图参考编辑 | 3 | `GetImageSize` 跟随 | 否 |
| PornMaster 三图角色合成 6步 | 3 | `GetImageSize` → `EmptyFlux2LatentImage(width,height)` | 否 |
| PornMaster 四图参考 6步 | 4 | 同上 | 否 |
| PornMaster 双图参考换衣 | 2 | 同上 | 否 |
| PornMaster 单图编辑 | 1 | 同上 | 否 |

**没有任何 0 图工作流**（最少 1 图）。

### 2.3 空槽目前不压缩，且有一处静默缺陷

- `roles = [item["role"] for item in inputs]`，由工作流 `LoadImage` **节点顺序**决定，与"哪些槽有图"无关；
- `source_groups = [provided[role] for role in roles]`，空槽对应组为 `[]`；
- `combos = list(itertools.product(*source_groups))`，任一维为空 → `[]`；
- `enqueue_submission(SubmitTask(job_id, list(range(len(combos))), prepare))` — **没有 `if not combos` 拦截**。

后果：放开必填后若不做处理，会**静默入队 0 张**（前端显示成功、实际无任务）。

### 2.4 提示词已支持"缺槽裁剪"，被两处堵住

`app/services/recipe_prompt.py` 已按槽位分块：

- `if portrait:` 才写「人物：脸型/五官/发型/发色」；
- `if costume:` / `if pose:` 各自独立；
- 内置 `faceless = not portrait and bool(costume and pose)` 分支，自动改为「无脸展示」「人物穿搭展示图」「脸部无五官」。

被堵住的原因：

1. 路由 `_resolve_slot()` 对三槽强制（`缺少{label}` 直接 400）；
2. `_slot_entry(None, key)` 把空槽包成占位对象，导致 `if portrait:` 恒为真，`faceless` 永不触发，且**编号错乱**（写「图1中的人物」但图 1 实际是服装）。

### 2.5 三处默认不一致

| 来源 | 值 |
| --- | --- |
| 前端下拉 `default` | `图库专用_QwenEdit_GGUF-Q5KM_三图_4步_标准` |
| 前端 ★ 推荐 | `图库专用_Qwen21+VNCCS_三图_25步_单人` |
| **后端实际执行** | **`PornMaster_Flux2Klein9B_三图角色合成_6步_自动尺寸`** |

## §3 方案设计

### 3.1 槽位与"或"的处理

按工作流类型分治，**不做运行时图重写**：

| 场景 | 处理 |
| --- | --- |
| 选中 **Qwen 系** 工作流 | 三槽任意空白。注入时按"实际有图的槽位"依次填入 `image_1..N`；提示词同步压缩编号 |
| 选中 **Flux 系** 工作流 | 三槽必须填满；未填满时**不允许提交**，并提示"当前工作流需要 N 张图，请补齐或切换到支持 X 图的工作流" |
| 槽位为空且用户未选工作流 | 按槽位数自动挑能力匹配的工作流：3→三图 / 2→双图换衣 / 1→单图编辑，**并在提交前显式告知"已切换到 XXX（语义变为换衣/编辑）"** |
| 全空 | 拒绝（至少 1 张图，0 图模式暂不做） |

**关键决策**：自动换工作流必须**显式可见**，否则又是"假控件"换了个马甲。

### 3.2 提示词裁剪

1. `_resolve_slot()` 改为"允许空，返回 None"；
2. 删除 `_slot_entry(None, key)` 的占位包装，直接把 `None` 传给 `build_recipe_prompt`；
3. 编号随实际图数重排（`build_recipe_prompt` 的 `if` + `idx += 1` 逻辑已支持）；
4. `faceless` 分支自动生效，产出「无脸展示」提示词；
5. 全空时由路由拒绝，不依赖 `build_recipe_prompt` 里那句"请先选择…"兜底。

### 3.3 批量（笛卡尔积）

- 输入：三个槽位各自的多选集合（Qwen 系可为空集）；
- 组合：`itertools.product(*非空组)`，空槽**不产生维度**；
- 护栏：`total > 100` → 400，文案沿用「全组合共 N 张，超过上限 100 张；请减少素材」；
- 新增护栏：`total == 0` → 400「请至少选择一个参考图」，杜绝静默 0 张；
- 进度：复用现有 job 队列 + SSE，前端展示 `已完成/总数`、失败项可单独重试；
- 停止：支持"取消剩余未开始的任务"。

### 3.4 种子

**前端派生，后端保持 `seed_mode=fixed`**：

```
seed_i = base_seed + i    // i 为组合序号
```

理由：可复现（记录 base_seed 即可整批重放）、可横向对比、后端零改动、任务列表可见每张 seed。

第一期**不做**"同一组合 × N 个种子"这一额外维度（会与组合数相乘，很快撞 100 上限）。

### 3.5 工作流接真与白名单

- `RecipeRequest` 新增 `workflow`（路径或名称）；
- 后端校验：必须解析到 `scope=studio` 的合法工作流，否则 **400**「该工作流不属于合成台可用范围」，**不静默回落**；
- 默认值统一为 ★ 推荐项（`Qwen21+VNCCS 三图 25步`）；
- 移除 `THREE_REF_WORKFLOW` / `FOUR_REF_WORKFLOW` 常量硬绑定（或降级为"未指定工作流时的兜底"）。

### 3.6 分辨率 / 横竖（R3）—— 复用既有能力声明机制，不需要新造

**更正上一版结论**：项目里**早已存在**统一的能力声明与尺寸注入机制。此前只解析了工作流 JSON 就下「没有尺寸入口」的判断，漏掉了 `workflow_parser` 这一层，属于判断过早。

#### 既有机制（实测存在）

| 层 | 实现 |
| --- | --- |
| 后端·能力检测 | `detect_workflow_caps()` 返回 `prompt` / `negative` / `negative_effective` / `quality` / `orientation` |
| 后端·尺寸注入 | `_inject_resolution()` 支持 `quality`（0.75x–2.0x）、`aspect_ratio`、`orientation`（portrait / landscape） |
| 后端·尺寸来源解析 | `_latent_info()` 识别四种模式：`literal`（字面宽高）/ `resolver`（ResolutionSelector）/ `preset` / `megapixels` |
| 后端·写回 | `_set_latent_size()` 直接把宽高写进 latent 节点 |
| 前端 | `useWorkflowCaps()` 按 caps 生成档位与比例，注释写明「不支持的项直接隐藏，不发无效参数」；组合器 `ComposerView` 已在用 |

#### 为什么参考库接不上（两道设计假设挡着）

1. `detect_workflow_caps()` 中 `has_image_input` 为真即 `continue`，注释是「图生图/编辑工作流的尺寸由输入图决定，不暴露比例和画质」——**一刀切**；
2. `_latent_info()` 只认字面量宽高或 Resolution* 类上游；PornMaster 的 `EmptyFlux2LatentImage.width/height` 连到 `GetImageSize`，四个分支都不匹配 → 返回 `None`。

实测结果：

| 工作流 | `detect_workflow_caps` | `_latent_info` |
| --- | --- | --- |
| Qwen21+VNCCS 三图 | quality=False, orientation=False | None（latent 来自 `TextEncodeQwenImage21`） |
| QwenEdit 三图 4步 | quality=False, orientation=False | None（latent 来自 `TextEncodeQwenImageEditPlus`） |
| PornMaster 三图 | quality=False, orientation=False | None（width/height 是 `GetImageSize` 连线） |
| PornMaster 四图 | 同上 | 同上 |

#### 结论（修正 R3）

| 工作流族 | 能否指定尺寸 | 需要做什么 |
| --- | --- | --- |
| PornMaster（三图 / 四图 / 双图 / 单图） | **能** | 补两处：`_latent_info` 增加 `linked-image` 模式（上游 `GetImageSize` → 用参考图实际尺寸作默认，允许被字面量覆盖）；`detect_workflow_caps` 对「有 LoadImage 但存在独立 latent 节点」的工作流不再一刀切跳过 |
| Qwen 系（Qwen21 / QwenEdit） | **不能** | latent 由文本编码器产出，无独立 latent 节点。要横竖只能输入侧缩放参考图（改变生成条件）或输出侧后处理 |

**因此 R3 从「改造工作流」下调为「扩展后端既有能力检测」**：不需要改 10 个工作流 JSON，不需要拉伸裁切，也不需要另造一套声明机制。前端直接复用 `useWorkflowCaps()`。

附：`EmptyFlux2LatentImage` 的 `width/height/batch_size` 均为 required 输入（ComfyUI `object_info` 实测），把连线换成字面量在协议层合法。

#### Qwen 系为什么不可指定（技术定性，实测）

`object_info` 实测 `TextEncodeQwenImage21`：

```
输入 required: clip, prompt, negative_prompt, resolution, images
输入 optional: vae
输出       : CONDITIONING, CONDITIONING, LATENT  (positive / negative / latent)
```

关键点：

1. **latent 由编码节点自己产出**，不是工作流里漏放了 `EmptyLatentImage`；
2. 该节点**没有 width / height 输入**，只有 `resolution`，其 tooltip 明确写「参考图会被缩放到约 resolution×resolution 像素，保持比例；0 表示各自保持原尺寸」——**只控制参考图缩放，不控制输出宽高**；
3. `TextEncodeQwenImageEditPlus` 同理：`required: clip, prompt`，`optional: vae, image1, image2, image3`，同样没有尺寸输入。

**结论：这是"编辑类模型 latent 跟随输入图"的范式限制 + 节点本身没有尺寸输入，不是本地工作流漏写参数。** 但它并非完全无解：

| 做法 | 可行性 | 代价 |
| --- | --- | --- |
| 调 `resolution`（Qwen21） | 可，影响参考图缩放与输出尺寸上限，**比例仍跟随参考图** | 小，但无法选横竖 |
| 输入侧把参考图缩放到目标比例 | 可，能真正出横图 | 需改工作流 + 重测姿势基线 |
| 输出侧 `ImageScale`/裁切 | 可，但属"假尺寸控制" | 小，会拉伸/裁切 |

#### 官方文档核对（ComfyUI docs / Qwen-Image-Edit）

官方原文要点：

- Qwen-Image-Edit 把输入图**同时**喂给 `Qwen2.5-VL`（视觉语义控制）与 **VAE Encoder**（外观控制）；
- 官方工作流用 **`Scale Image to Total Pixels`** 把输入图缩放到约 1M 像素，目的是避免 2048×2048 这类超大输入造成质量损失；
- 官方没有任何"输出宽度/高度"设置项。

**据此更正上一版的说法**：Qwen 系**并不是"不支持横图"**，而是——

> **输出画幅跟随输入图**。输入是横图，输出就是横图；输入是竖图，输出就是竖图。

准确表述：

| 说法 | 是否正确 |
| --- | --- |
| "Qwen 不支持横图" | **错误**，已更正 |
| "Qwen 不能通过参数强制指定横竖" | **正确**：无 width/height 输入，`resolution` 只控制像素总量、保持比例 |
| "Qwen 要出横图，就得让输入图是横的" | **正确**，官方 `Scale Image to Total Pixels` 就在输入侧 |

因此与 Flux 系不同：**PornMaster 能真正做到"指定宽高"；Qwen 系是"输入什么比例就输出什么比例"，`resolution` 只能调像素总量（0.75x–2.0x 可映射为 768/1024/1536 等）**。

#### `resolution` 映射核验（依据 ComfyUI 节点官方定义，非推测）

`object_info/TextEncodeQwenImage21` 实测返回：

```
resolution: INT, default=1024, min=0, max=4096, step=32
tooltip: "Reference images are resized to about resolution x resolution pixels,
          at multiples of 32, preserving aspect ratio. 0 keeps each reference at
          its own size, rounded to a multiple of 32."
```

据此核验项目既有 `quality` 档语义（`quality_scale("1.0x") = 1.0`，用于 `megapixels * scale²`）：

| 档位 | 线性倍率 | → resolution | 语义核对 |
| --- | ---: | ---: | --- |
| `0.75x` | 0.75 | **768** | 参考图边长 ×0.75，像素面积 ×0.5625；与 `scale²` 语义一致 |
| `1.0x` | 1.00 | **1024** | 等于节点默认值，**保持当前行为不变** |
| `1.5x` | 1.50 | **1536** | 像素面积 ×2.25 |
| `2.0x` | 2.00 | **2048** | 像素面积 ×4；max 4096 之内，但**耗时未实测，可能触 180s 价值线** |

结论：**映射在语义上成立**，因为 `resolution` 是"参考图缩放后的边长基准"，与既有 `quality` 的线性倍率一一对应；**但它是"像素总量"而不是"输出宽高"**，输出尺寸仍由缩放后的参考图比例决定。

因此本期的处理是：

- **不把 Qwen 的 `resolution` 纳入首期尺寸档**（`_latent_info()` 目前不识别 `TextEncodeQwenImage21`，返回 `None`，强行注入也不会生效）；
- Qwen 系一律 `caps.quality = false / caps.orientation = false`，前端**隐藏**尺寸与横竖控件，发送前按 caps 过滤参数；
- 记录为「未来可选项」：若要做，需给 `_latent_info()` 增加 `text-encoder-resolution` 模式，并先实测 1.5x / 2.0x 的耗时。

### 3.7 批量维度（R11：尺寸可多选）

组合数计算：

```
total = (非空槽位组合数) × (选中的画质档数) × (选中的比例数)
```

- 对 **Flux 系**：画质档与比例都可多选；
- 对 **Qwen 系**：`caps.quality=false` / `caps.orientation=false`，两个维度都固定为「不参与」（各计 1），实际只剩槽位组合；
- 上限仍统一为 **100**：`total > 100` → 400「全组合共 N 张，超过上限 100 张；请减少素材或尺寸档位」；
- 前端实时显示 `槽位组合 × 尺寸 × 比例 = N`，超限直接禁用提交并给文案，不等后端报错；
- 种子仍按 `base_seed + i` 派生（i 为最终组合序号），保证整批可复现。

**风险提示**：3 人像 × 3 服装 × 3 姿势 × 2 档 × 2 比例 = 108，已经超限。所以多选尺寸会显著抬升组合数，UI 必须把「当前 N / 上限 100」常驻展示。

## §5 验收标准（编码完成后逐条实测）

1. 三槽任意空白，Qwen 系工作流可正常出图，提示词不含"人物：脸型五官"段（无脑补）；
2. 提示词编号与注入图数量严格一致（空槽后 `图1` 就是第一张实际图）；
3. 笛卡尔积 3×3×3=27 提交成功，任务数与组合数一致；超过 100 拒绝并提示；
4. 空槽时组合数 = 非空维度乘积（不是 0）；
5. 全空提交 → 400「请至少选择一个参考图」，不是静默 0 张；
6. 选 Flux 系 + 槽位不满 → 拒绝并告知需要 N 张；
7. 工作流下拉切换后，**后端实际执行的就是所选工作流**（抓 request body + 任务落点验证）；
8. 传入非 studio 工作流 → 400，不回落；
9. 批量种子 = base + i，可用 base 复现整批；
10. 尺寸：PornMaster 系选横版后产物宽高为目标值；Qwen 系页面显示"跟随参考图"且与产物实际尺寸一致。

### 7.1 默认工作流：三候选对比（**本轮已执行，后续不重复**）

**本轮对比口径**（已下发执行，不再重复）：

1. **唯一三项无短板且姿势落地的是 Qwen21**：人脸 4 / 服装 4 / 姿势 4，姿势为「单膝跪地 + 双手抱头后」，属于坐蹲类，宽高比 0.65 同时落在坐蹲区间（0.52–1.0），视觉判定与数值判定一致。
2. **QwenEdit 姿势 1 分**：产物完全站直、双手下垂提包，与「单膝立起/坐蹲」无关；宽高比 0.45 落在站立区间（0.30–0.40）之上、坐蹲区间之下，属无效区。另外草帽把脸完全罩住（放大复核确认眉眼鼻嘴均不可见），**人脸一致性未能验证**，不能给通过。
3. **PornMaster 是「宽高比陷阱」的反例**：0.55 虽落在坐蹲区间，但放大下半身复核为「单腿站立 + 右踝搭左膝」，臀部离地约身高 55–60%，并非坐蹲；姿势仅 2 分。其服装 3 分（草帽与草编包缺失、短裙应为蜜桃粉却生成蓝色、长袜变短袜），人脸 4.5 是三候选中最好的，但不足以抵消姿势与服装的硬伤。耗时 52.4s 最短，但时间不是分水岭（三者均 ≤180s）。
