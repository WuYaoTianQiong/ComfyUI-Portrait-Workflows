## 六、失败项清单（每条：现象 / 复现 / 判定 / 建议）

### 1. e2e 参考图库断言过期 —— **断言过期（已按授权修复）**

- **现象**：`python tests/e2e/run_e2e.py` 在 `page.click("button:has-text('参考图库')")` 处 `TimeoutError 30000ms`；此前的旧断言还依赖 `.reference-page`、`.tab-row .tab`、`.jgrid .jcell`、`.nsfw-toggle`、`.sheet-btn`，这些 DOM 在 E 之后已不存在。
- **复现**：`cd 脚本\atelier && python tests\e2e\run_e2e.py`
- **判定**：**断言过期**，非回归。导航项已由 `<button>` 改为 `<a href="/ref-web">`，页面已换成上游 React 台。
- **处理**：按 §25.4 授权改为 `/ref-web` 深链接验收（详见 §八）。

### 2. 顶栏入口断言还需显式等待 6.5s 的慢接口 —— **断言脆弱（已按授权修复）**

- **现象**：替换后的断言首跑仍失败 2 条（`顶栏有参考图库入口 | 0 个`）。实测逐秒采样：`a_count` 在页面加载后 **t=8.2s** 才变 1。
- **根因**：入口由 `/api/system/status` 的 `reference_web_url` 驱动，而该接口在 ComfyUI 离线时要 **6.4–6.6s**（`is_online()` 5s 超时 + 重试 2 次），e2e 跑到该断言时结果还在路上。
- **复现**：起服务后 `GET /api/system/status`，服务日志 `[atelier] GET /api/system/status -> 200 6609ms`；浏览器里顶栏 `<a>` 延迟出现。
- **判定**：**断言脆弱**（时序依赖），不是业务回归；但慢接口本身是真实的产品体验问题（见 §七-3）。
- **处理**：断言前加 `wait_for(state="visible", timeout=25000)`。

### 3. `npm run build` 在 IDE 环境下失败 —— **环境限制（已在 §11 加固）**

- **现象**：`error during build: [safe-delete] 操作失败: … web\assets: Error during a 'trash' operation: Unknown { description: "Some operations were aborted" }`（栈指向 `node-safe-delete-shim.cjs`）。
- **复现**：`cd frontend && npm run build`（在注入了 `NODE_OPTIONS=--require …node-language-shim.cjs` 的 IDE 终端）
- **判定**：**环境限制**（IDE 的回收站保护 shim 拦截 `rmSync`），与代码无关。
- **处理**：`$env:NODE_OPTIONS=''; npm run build` → **通过**（5.88s）。建议 `tools/ci.ps1` 在构建步骤前也清空该变量，否则 CI 在 IDE 终端里跑会假失败。

### 4. 硬编码颜色未清零 —— **未达标（已在 §11 归零）**

- **现象**：`18 处 / 6 文件`（基线 55 / 20）。
- **复现**：见 §三 统计命令。
- **判定**：**未达标**。其中 `TaxonomyView.vue` 的 8 处是"分类调色板"数据色，硬套令牌并不合适；`ReferenceView.vue`/`RefLightbox.vue` 的 6 处属死代码，随文件删除即可归零。
- **建议**：把 `ci.ps1` 基线从 55 **收紧到 18 以下**（否则守护无意义），死代码删除后收紧到 10。

### 5. `web/assets` 历史产物不清空 —— **工具链问题（已在 §11 修）**

- **现象**：`web/assets/` 里有 **13 份** `index-*.js`（17:31 → 19:29）+ 5 份 `ReferenceView-*.js`，`web/` 合计 **52.7MB**；`vite.config.ts` 已写 `emptyOutDir: true`，但连续两次 build 后数量仍为 13、最新的仍是上一次的 `index-Dek3Wqb0.js`。
- **复现**：`cd frontend; npm run build` 两次，`(Get-ChildItem ..\web\assets\index-*.js).Count` 恒为 13。
- **判定**：**工具链问题**，不是本次改动引入。归因已澄清：这里指的是 atelier 自己的 `frontend → ../web`（`outDir` 在 Vite root 之外的跨目录输出）；与 `gallery-web` 用默认 `dist` 的情况不同 —— §10.1 已证明后者的 `--emptyOutDir` **确实有效**，本节的现象不能拿来否定它。
- **影响**：`index.html` 只引用最新 chunk，运行期无害；但磁盘浪费，且一旦某次 `index.html` 写入失败，会**静默回退到仍存在的旧 chunk**（不会 404，极难发现）。
- **处理**：§11 在 `ci.ps1` 里 build 前显式删除 `web/`，实测 build 后 `assets` 恒为 3 个文件 / `web/` 4.0MB。

### 6. 工作树不干净 —— **流程偏差（按用户指示保持现状）**

  - `M frontend/src/views/ReferenceView.spec.ts`（+44）

- **判定**：违反 §25.1「工作区必须为空」。已按用户决策**保持现状继续验收**：本报告的所有数字均基于**含这 3 个未提交改动的工作树**；这些改动本会话未提交、未丢弃。
- **影响**：`reference_library.py` 是活代码（已计入门禁结果）；`ReferenceView.*` 是死代码（仅影响 §三 中 `ReferenceView.vue` 的 5 处硬编码色计数，其中 1 处由本次未提交改动引入）。
