### 1.3 架构现状

```
两个工作台（薄壳）      Composer（文本/碎片）      Studio（三槽参考合成）
        ↓                        ↓                         ↓
一个前端数据层          api/<domain>.ts + 生成类型 + ApiError
        ↓
四个后端底座
  1. submit_generation   建 job / 幂等 / 队列 / 命名 / 归档 / SSE
  2. compile_prompt      解析 → 负向归并 → 否定规则 → 渲染（两语法适配器）
  3. assets              寻址 / 缩略图 / 定位 / 存在性 / 删除
  4. workflow.inspect    caps / params / 尺寸 / 画质档（后端唯一真源）
```

| 底座 | 文件 | 职责 |
|---|---|---|
| 提交 | `app/services/generation.py` | 建 job、输出子目录、同步推送 / 后台入队 |
| 编译 | `app/services/prompt_compiler.py::compile_for_submission` | 注入 / 预览 / 快照共用编译决策 |
| 资产 | `app/services/assets.py`（+ `asset_store.py`） | 本地文件 / ComfyUI 代理 / 缺失占位三态 |
| 工作流能力 | `app/services/workflow_parser.py` + `/api/workflows/inspect` | caps / params / size_preview 后端唯一真源 |

**差异保留在交互范式，不保留在数据链路**：Composer 与 Studio 必须走同一套提交、编译、资产与任务语义。

## ③ 关键决策与理由

### 3.1 路线级

1. **先地基后功能**（2026-11-07 拍板）：先把契约、提交、编译、资产收成单点，再谈功能。理由：诊断显示「同一能力被独立实现多次」才是主要成本来源。
2. **允许小改数据模型 + 迁移**：只加列/加表/加索引，兼容旧数据，**不删除既有列**；迁移只追加版本号，不改旧版本。任何 DB 变更前 `python tools/backup_db.py --tag before_<batch>`。
3. **双入口共享底座**：Composer（文本/碎片）与 Studio（三槽参考合成）保持双入口，共享提交/编译/资产/工作流能力四底座。
4. **第一轮按功能波浪、第二轮按不变量收敛**（2026-11-07）：第二轮审计发现剩余问题几乎都是**跨域不变量失守**（身份/状态/文本/生命周期/契约），因此原则改为「局部实现为不变量让步，不再为单个功能新增旁路」。
5. **巨型 view 拆分只搬运、不改行为**：每步拆一个区块，用现有 spec + E2E 回归；避免「拆分 + 改行为」混在一起无法定位回归。

### 3.2 数据与身份

| 决策 | 理由 | 证据 |
|---|---|---|
| workflow 身份 = `wf-<sha1(路径)[:12]>` + `sha256`，文件名只作显示标签 | 改名/换目录后历史任务仍可追溯 | `workflow_manifest.py` 设计注释：「文件名只是显示标签，不能当身份」 |
| `工作流清单.json` 与 `资产清单.md` **不能合并** | 机器身份 / 人读知识，生产者与消费者都不同：json 由程序生成、被 `job_state.py` 等程序消费；md 必须实测才有（耗时、坑、选型理由） | 详见 `重构审计/文档治理_计划_20261112.md` §1.1 |
| 画质对外键统一 `0.75x…2.0x`，旧 `2K…12K` 只做读取别名，默认 `1.0x` | 旧键是相对倍率，切工作流会静默改实际像素 | 见 1.4「B6 分辨率契约」 |
| `entity_tags` 为标签真源，`prompts.tags` 降为派生缓存 | 双真源导致改名「复活」、计数分叉 | P1-D；`tests/test_tags.py` |
| 分类身份 = `id + system_key`，禁止按名字匹配 | 改名会失联或重生默认分类 | v7 迁移；`test_category_system_key.py` |
| 幂等键独立成列 + `(scope, key)` 唯一索引 | 并发双击只建一个任务 | v8 迁移；`test_idempotency.py` |
| `file_tombstones` 墓碑表 | 软删后磁盘扫描会把文件重新收编 | P0-C；`test_p0_files.py` |

| 时间戳/`captured_at`、墓碑回收 | 见 B4 数据语义三条 | 附录 B.1 |

### 3.4 工程约定（违反会直接坏）

1. **一次一批提交**：改名与改行为分开；并发工作区只提交自己的文件；同一文件混批次时用 hunk 级暂存。提交前 `git status`。
2. **契约生成**：改 `schemas.py` / 路由后必须 `python tools/gen_api_types.py`；CI 比对生成物哈希，否则 `test_openapi_snapshot` 红。
3. **CRLF 仓库**（`core.autocrlf=true`）：批量改文件后确认没混入 LF；前端构建产物 `web/` 入库。`gen_api_types.py` 的换行**不改**，交给 git 行尾转换处理（强行改 LF 会让 CI 前后哈希比对必然假红）。
4. **SQLite 单进程**：`job_state` 单写者 + 内存队列，不支持多 worker。
5. **测试隔离**：pytest 用临时库（`tests/conftest.py` 隔离 DB/缩略图/ComfyUI 根/`library_root`）；禁止静默 `pytest.skip`，skip 必须带原因并计入 CI 摘要。
6. **路径校验不能用 `Path.resolve()`**：Windows junction 可能抛 `WinError 448`，统一走 `_resolve_if_reparse` 容错。
7. **不自动 commit / revert / stash 其他会话改动**。
