## 1. 问题确诊（评审结论，作为设计约束）

1. **载体模型不该暴露**：试外来文本必须先选一条无关提示词当载体，面板预填载体全文，用户要全选删除再粘贴。
2. **同一文本两个可编辑副本**：主编辑框草稿 vs 面板文本框，打开时拷贝一次，之后互不同步。
3. **四个"跑文本"入口**：出图 / 试跑 / 变体 / 替换碎片，区别只是实现细节（写不写库、挂不挂名、几张）。试跑一张+随机种子 ≡ 变体选 1 张。
4. **出图悄悄跑旧文本**：`/api/runs` 只传 id，后端读**已保存**文本（`comfyui.py:384`），编辑框里未保存的修改不参与出图——界面上没有任何提示。
5. **试跑日志达不到目的**：localStorage 只存 60 字截断预览+种子，无全文、无图、点不动；"试完满意再保存"的保存路径不存在。
6. **隐形关联魔法**（本轮已上线但应废弃）：文本逐字节等于草稿才挂载体名下，否则标临时提示词——同一按钮两种归档行为，不可预测。
7. **负向暗箱**：试跑面板偷用载体负向，不展示不可改。

## 2. 参照

- **ComfyUI 本体**：一个 Queue Prompt 主按钮 + 旁边 batch count。用户已经熟悉这个模型，出图栏直接对齐。
- **Linear / Notion**：一个界面一个主操作，次要操作收进溢出菜单；保存是显式动作，不靠隐式写回。
- **ChatGPT 临时对话**：scratch 与已保存资产分离，临时产物可一键转正。

## 3. 统一动作模型

"跑图"只有一个动作，六个**显式**参数：

```
跑图(文本, 负向, 工作流+画质+比例, 张数, 种子, 归档关联)
```

- 张数 1 = 旧"试跑一张"；张数 N = 旧"变体"（种子依次 +1）。**不再有试跑/变体两个概念。**
- 归档关联是看得见的选择：「不关联（临时提示词）」或「关联到《某提示词》」。**不做文本比对魔法。**
- 文本永远所见即所得：跑的就是眼前编辑框里的内容。

两个界面填这六个参数，复用同一套组件（WorkflowPicker / WorkflowParams / Modal / useGenerate）：

| 界面 | 文本来源 | 归档关联 | 场景 |
|---|---|---|---|
| A. 详情页出图栏 | 当前编辑框（草稿） | 固定=当前提示词（界面已明示） | 库内提示词的日常出图/微调 |
| B. 临时试跑面板 | 空白的粘贴框 | 默认不关联，可显式选择 | 外来文本试跑、随手实验 |

## 4. 设计 A：详情页出图栏

```
[工作流 ▾] [画质/比例 …]                 [✂ 智能分段] [替换碎片]
                                          张数 [1|2|3|4]  种子 [  空=随机  ]  [▶ 出图]
```

- **出图 = 跑编辑框当前文本**。草稿有未保存修改时，按钮旁显示「含未保存修改」徽标；出图不写库、不要求先保存。
- 张数选择器 1–4（默认 1），种子输入框（空=随机；提示词存了种子则作为默认值填入）。张数>1 时种子依次 +1。
- **删除「🧪 试跑」「🎲 变体」两个按钮**。旧"改草稿试跑"场景由"出图跑草稿"直接覆盖。
- 智能分段、替换碎片保留：它们是文本**编辑**动作，不是跑图入口（替换碎片有自己的批量出图流，不动）。
- 归档：出图永远关联当前提示词，`prompt_params` 存当次实际文本（含未保存修改），档案可回看。

## 5. 设计 B：临时试跑面板（独立入口，无载体）

**入口**：/prompt 左侧工具栏 `[+ 新建] [导入] [导出]` 旁加 `[🧪 试跑]`。**不依赖选中任何提示词**，空库也能用。

**面板**（Modal，宽 720px）：

```
┌ 临时试跑 ───────────────────────────────┐
│ 提示词                                  │
│ ┌─────────────────────────────────────┐ │
│ │（空框，placeholder：粘贴想试的提示词）│ │
│ └─────────────────────────────────────┘ │
│ 负面提示词  [＋ 添加]（默认收起，可编辑）  │
│ [工作流 ▾] [画质/比例 …]（与详情页同组件） │
│ 张数 [1|2|3|4]  种子 [  空=随机  ]        │
│ 归档到： (●) 不关联（临时提示词）         │
│         ( ) 关联到《当前选中的提示词名》   │ ← 仅在有选中条时出现
│                              [▶ 跑图]   │
│ ───────────── 本次结果 ──────────────── │
│ [缩略图] 种子 12345 · 已完成   [看图][存为提示词] │
│ [缩略图] 种子 12346 · 跑图 2/4 …         │
└─────────────────────────────────────────┘
```

- 打开是**空框**，不带任何载体文本。从某条提示词上下文打开时，归档选项里多一个显式选项，默认仍是不关联。
- 负向可见可编辑，工作流不支持时显示「负向不生效」（沿用现有能力徽标）。
- 工作流/画质/比例读写全局设置（useSettings），与详情页保持一致，不另起一套。

## 6. 结果区与保存闭环

- 提交后结果区出现**真实任务行**：状态 → 完成后出缩略图。复用 `useGenerate` 队列模式（SSE 订阅、job id 落盘、刷新后按 id 恢复），不新造状态机。
- 每条结果两个动作：
  - **看图**：打开灯箱，档案里就是当次全文（`prompt_params`）。
  - **存为提示词**：打开现有 PromptCreateModal，**预填当次实际文本 + 负向 + 种子**，保存后左栏出现新提示词。试→满意→存的环闭合。
- **删除旧试跑日志**（`pb.trialLog` 截断预览）：结果区就是日志，有图、有全文、能点。localStorage 存 job id 列表用于恢复；另存一份 `pb.trialRuns`（job id → 当次文本/负向/种子，上限 20 条），只服务"刷新后仍能预填存为提示词"——任务快照的 `JobItem` 只有 40 字预览，拿不到全文。
- 详情页出图同样使用队列模式：张数 >1 时全部任务都被跟踪，不再只跟最后一个；`busy` 在提交请求结束即解除，progress 由任务队列推进。
- 已生成的图不做"重关联到新提示词"（见 §9）。

## 7. 行为对照（旧 → 新）

| 场景 | 旧 | 新 |
|---|---|---|
| 跑编辑框里改过的文本 | 试跑面板（载体预填，再覆盖） | 直接点出图 |
| 跑已保存文本 | 出图（悄悄跑旧文本，无提示） | 撤销修改或保存后出图（所见即所得） |
| 外来文本试跑 | 选载体→覆盖草稿→开面板→再覆盖面板文本框 | 左栏试跑→粘贴→跑图 |
| 同文本多种子出 N 张 | 🎲 变体→面板→选张数 | 张数选 N |
| 试完想保存 | 断路（手动抄回，覆盖载体） | 结果行→存为提示词（预填） |
| 回看试过什么 | 60 字截断日志 | 结果区真图真全文 + 画廊档案 |
| 图挂在哪 | 文本比对魔法 | 界面上显式选择 |

## 9. 刻意不做

- 不动组合器 / 参考图库 / 图像编辑的出图入口（属全局收敛另一条线）。
- 不做"已出图重关联到新建提示词"：档案全文已可回看，重关联要新端点，收益不成比例，单列。
- `/api/runs` 不删除：e2e 与其他调用方在用；不传 override 时行为不变。
- 不动 `【类型】` 碎片语法与智能分段。

## 12. 拍板结论

1. **出图跑草稿（所见即所得）** —— 已落地。替代方案（dirty 时「保存并出图」）未采用。
2. **试跑入口在左栏工具栏**（新建/导入/导出旁）—— 已落地；侧栏折叠态另有 `🧪` 按钮。替代方案（顶栏全局入口）未采用。
3. **旧试跑日志直接删**（结果区取代）—— 已落地。
4. 追加决策：结果行「存为提示词」需要当次全文，localStorage 在 job id 之外另存 `pb.trialRuns`（≤20 条）；否则刷新后只能拿到 40 字预览。
5. 追加决策：详情页出图 `useGenerate` 切队列模式，张数 >1 时全部任务都被跟踪。
