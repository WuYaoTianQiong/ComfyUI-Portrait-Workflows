# 替换碎片弹窗设计优化 · 2026-11-01

## 目标

把「替换碎片出图 / 批量替换碎片」从「紧凑表单 + 两张列表」重排为：

**上下文条（类型 / 范围 / 工作流） → 浏览区（替换内容 + 候选） → 差异核对区（逐条旧→新 + 结果摘要）**

业务目标：在提交前能一眼确认「用哪个工作流出图、会影响哪些提示词、每条具体改什么」，降低跑错工作流或改错提示词后浪费整批 GPU 任务的风险。

## 实测依据（1440×900 / 1024×768，暗色）

| 指标 | 现状 | 结论 |
| --- | --- | --- |
| 工作流名称 | 可用 242 / 266px，完整需要 271px | 两种宽度都截断 |
| 步骤行 | 1440 下一行 10 个控件；1024 折两行，「重置」孤立 | 控件平铺，没有分组 |
| 右侧列表 | 481px 高、行高 27px；单条空白 452px | 94% 面积空着 |
| 新内容可见 | 1440 下 243px / 需要 737px；1024 下 144px | 差异不可读 |
| 候选列表 | 218 条只可见 5 条（1440）/ 4 条（1024） | 搜索成为硬依赖 |
| 字号 | 元信息 10px，计数/说明 11px | 弱信息过小 |

## 改动清单

### P0 · 业务风险

- [x] 工作流回到上下文行，并吃掉剩余宽度；完整名称不截断
- [x] 右侧改成逐条差异卡：旧块/新块完整换行；追加行不画删除线
- [x] 差异卡提供「完整提示词」展开；单条模式默认展开
- [x] 右侧顶部固定结果摘要：替换 X · 追加 Y · 跳过 Z
- [x] 主按钮按实际结果动态：`替换 3 条并出图` / `追加 1 条并出图`

### P1 · 布局效率

- [x] 上下文拆两行：类型/范围/工作流 + 缺少策略/重置/提示
- [x] 左侧输入固定 104px，候选列表吃满剩余高度（约 6 行可见）
- [x] 正文字号 12px、元信息 11px，计数/说明不再用 11px 低对比
- [x] 右侧无匹配行时给可操作空状态（换类型 / 追加）

### P2 · 打磨

- [x] 锁定提示词从控制行移到右侧标题区，改成只读上下文 chip
- [x] 「追加」只保留行状态 + 摘要 + 主按钮，去掉重复计数
- [x] 检索时显示「已选 X / 可见 Y / 隐藏 Z」，避免反选漏项
