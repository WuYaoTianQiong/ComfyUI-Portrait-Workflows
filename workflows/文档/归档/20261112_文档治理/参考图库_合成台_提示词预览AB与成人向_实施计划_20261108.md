## 2. 现状诊断（已用真实 dry-run 复现）

### 2.1 预览乱

`StudioPromptEditor.vue`（`frontend/src/views/reference/components/reference/StudioPromptEditor.vue`，约 L236-L271）把每个条款都渲染成同权重的带边框卡片（标签 + 来源 + 字数 + textarea）。双人场景实测 7~9 段长文全部堆在 7/12 宽栏，没有分组或折叠。

### 2.2 看不出 A/B

- `recipe_prompt.py` 双人分支（约 L434-L468）把 A 的脸型/服装写进同一条 `• 双人要求：…人物A：…；人物B…`，B 的细节又在后面的 `• 人物B（文字设定）`，A/B 交叉混排。
- `promptSegments.ts` 的 `segmentTone`（约 L183-L190）因为 `人物B（…）` 也以「人物」开头，返回和 A 完全一样的蓝色（portrait）。
- 同文件 `slotKeyOf` 也把 `人物B（文字设定）` 误判为 portrait 槽，来源提示错写成「图片」。
- 最严重：`recipe_prompt.py` bare 分支（约 L434-L444）优先命中，**完全不渲染任何 B 条款**。

真实 dry-run 证据（bare + 双人 + 传 B 文本）：

```
请求：person_b_portrait_text='金发碧眼، 丰满身材'，person_b_text='体型高挑'
输出 prompt 中没有出现「人物B」任何字样。
```

### 2.3 NSFW 被正向条款对冲

bare 双人实测输出含：

```
• 双人要求：…保持中性、非性化姿态…
• 素体展示：…保持中性、非性化的站姿或姿势构图，不添加任何性暗示元素。
```

非 bare 双人固定含：`不得出现性器官、胸部、臀部裸露`。

`prompt_compiler.py` 的否定抽离（约 L71-L73）只认 `避免|不要|禁止`，认不出「不得出现 / 不添加」，所以这些抑制词全部留在正向。负向实测只有「文字/水印/多人/缺肢体」等，没有性相关内容。

### 2.4 素体开关销毁服装

`useReferenceRecipe.ts`（约 L1114-L1131）`setBodyMode('bare')` 直接调用：

```
draft.removeCostume()
draft.removePersonBCostume()
draft.clearExtraCostume()
```

用户已选服装被清空，切回服装模式也无法恢复。

#### 4.4 `frontend/src/composables/promptSegments.ts`

新增：

```ts
/** 段归属：人物A / 人物B / 共用约束。 */
export type PromptSegmentOwner = 'A' | 'B' | 'shared'

/** 按标签前缀判定归属；人物B 必须先于「人物」判断。 */
export function segmentOwner(label: string): PromptSegmentOwner {
  const name = label.trim()
  if (labelStartsWith(name, '人物B')) return 'B'
  for (const prefix of ['人物', '服装', '姿势', '发型', '附加参考', '此外需体现']) {
    if (labelStartsWith(name, prefix)) return 'A'
  }
  return 'shared'
}
```

## 7. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 拆条改变提示词语义 | 双人出图人数/服装还原可能波动 | 批次 1 后先跑原有 324 条姿势风险表外的冒烟样本；异常则回退拆条，仅保留 bare-B 修复 |
| adult_mode 放开抑制条款 | 非预期裸露/多人 | 仅 18+ 解锁 + 后端总闸双校验；默认 false；保留四肢/人数约束 |
| 素体保留服装的计数遗漏 | 工作流适用性/裁剪判断错误 | `slotHasImage`、`filledSlotNames`、`filledSlotRoles`、`extra_costume` 发送四处同步门控 |
| 预览分组与原文顺序不一致 | 用户误以为提交顺序变化 | 组头注明「分组仅用于阅读，提交仍按原顺序」 |
| 既有测试断言硬编码旧文案 | 测试红 | 逐条按新结构更新，不做无关测试改动 |

回滚粒度：三个批次各自独立，可单独回退；不修改工作流与模型文件，回滚不涉及素材。
