## 0. 诊断摘要

功能本身大多在线，问题集中在"同一能力被独立实现多次"：

| # | 根因 | 主要证据 |
|---|---|---|
| 1 | 提交链路 5 份副本、批量 4 种模型 | `app/routers/comfyui.py`、`composer.py`、`images.py`、`editor.py`、`app/services/job_retry.py` 各自建 job + 注入 + push |
| 2 | 编译 4 个入口且顺序不一致 | 单跑/批量先 `strip_headers` 再编译（`comfyui.py`），`【避免】` 在编译器内部才处理（`prompt_compiler.py`） |
| 3 | 图片寻址 8 套、缩略图 4 入口 | `api/media/image`、`api/media/thumbnail`、`api/images/{id}/download`、`/api/browser/*`、静态挂载、参考库 `?kind=` |
| 4 | 前后端同算一遍 | caps / 尺寸 / 画质档：`useWorkflowCaps.ts` vs `workflow_parser.py`，口径已分叉 |
| 5 | 数据模型双真源 | `prompts.tags` 文本 vs `entity_tags`；`usage_count`；分类按名字当身份；`fragments` 死表 |
| 6 | 前端 4 个巨型文件 + 161 处手写 `/api` | `useReferenceRecipe.ts` 3187 行、`PromptView.vue` 2753、`ComposerView.vue` 1915、`GalleryView.vue` 1737；契约只覆盖 33/121 端点 |

## 1. 目标形态

```
两个工作台（薄壳）      Composer（文本/碎片）      Studio（三槽参考合成）
        ↓                        ↓                         ↓
一个前端数据层          api/<domain>.ts + 生成类型 + ApiError
        ↓
四个后端底座
  1. submit_generation   建 job / 幂等 / 队列 / 命名 / 归档 / SSE
  2. compile_prompt      解析 → 负向归并 → 否定规则 → 渲染（两语法适配器）
  3. assets              寻址 / 缩略图 / 定位 / 存在性 / 删除
  4. workflow.inspect    caps / params / 尺寸 / 画质档（后端唯一真源）
```

差异保留在交互范式，不保留在数据链路：Composer 与 Studio 都必须走同一套提交、编译、资产与任务语义。
