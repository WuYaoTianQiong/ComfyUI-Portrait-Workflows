# atelier UI「卖相」提升计划

> 版本：v1（2026-11-04）
> 目标：把 atelier 从"能用的工作台"提升到"看起来像个产品"——**只动样式与交互细节，不改信息架构、不加新功能**。
> 参照物：`ai-pose-gallery-zh` 的 React 台（截图见 `.screenshots\gallery-{poses,costumes,portraits,studio}.png`）。
> 关联：[AI参考图库_atelier融合计划](./AI参考图库_atelier融合计划_20261104.md) §15.7（设计语言清单）。

---

## 0. 一句话结论

差距**不在框架、不在组件库**，在于**设计系统的执行度**：令牌没被强制、组件没有 variants、版式没有节奏、微交互几乎缺失。

---

## 1. 现状诊断（实测数字，可复核）

| 指标 | 实测 | 说明 |
|---|---|---|
| 设计令牌 | `tokens.css` **33 个变量 / 157 行** | 已有 bg/panel/border/text/primary/success/warn/danger、fs、gap、radius、shadow |
| 前端页面/组件 | 41 个 `.vue`（30 个组件） | 规模不大，样式收口成本可控 |
| 硬编码颜色 | **55 处，分布在 20 个文件** | `PromptView` 9、`TaxonomyView` 9、`MaskEditorModal` 6… |
| 硬编码 px | **976 处** | 间距/尺寸基本没令牌化，这是"不精致"的最大来源 |
| `transition` 声明 | **18 处 / 41 个文件** | hover/选中/展开缺少过渡，界面"硬" |
| 前端单测 | 34 个 spec | 样式改动有回归基础 |

对照上游的四条差距：

| 维度 | 上游（React 台） | atelier 现状 |
|---|---|---|
| 令牌使用 | Tailwind theme 全量令牌，几乎无写死值 | 令牌有，但 976 处 px、55 处色值绕过它 |
| 组件层 | shadcn/ui：2,872 行原子组件 + variants | 30 个业务组件，状态样式各写各的 |
| 版式节奏 | 暗底 + 统一比例 + 留白刻度 + 动效 150–200ms | 卡片密度低、边框阴影不统一、动效稀薄 |
| 图表/空状态 | 图标集统一（lucide）、空状态与骨架屏齐全 | 空状态零散、无骨架屏 |

另一条根因：atelier 是**工作台**（要吞吐），上游是**展示页**（要卖相）。所以本次只补"表现层"，不动工作流。

## 2. 改进项（按投入产出排序）

### P0 · 令牌收口（0.5 天，收益最大）

**做什么**

1. 扩 `tokens.css`，补齐缺失的四组刻度（现有 33 个变量的基础上）：

```css
/* 间距：4 的倍数，只允许用这 8 档 */
--gap-xs: 4px;  --gap-sm: 8px;  --gap: 12px;   --gap-md: 16px;
--gap-lg: 24px; --gap-xl: 32px; --gap-2xl: 48px;
/* 字号 + 行高成对 */
--fs-xs: 12px; --lh-xs: 1.5;  --fs-sm: 13px; --lh-sm: 1.55;
--fs-md: 15px; --lh-md: 1.6;  --fs-lg: 18px; --lh-lg: 1.4;
--fs-xl: 24px; --lh-xl: 1.3;
/* 圆角 / 阴影 / 动效 */
--radius-sm: 6px; --radius: 10px; --radius-lg: 14px; --radius-pill: 999px;
--shadow-1: 0 1px 2px rgb(0 0 0 / .18);
--shadow-2: 0 4px 16px rgb(0 0 0 / .22);
--shadow-3: 0 12px 32px rgb(0 0 0 / .28);
--ease: cubic-bezier(.2, .7, .3, 1);
--dur-fast: 140ms; --dur: 180ms;
```

2. 把 55 处硬编码颜色替换为令牌（4 个 `status` 色 + 3 档 panel 足够覆盖）。
3. 把明显可归类的 px 换成间距/字号令牌（**只换语义明确的**，布局尺寸如 `width: 320px` 保留）。
4. CI 加一条守护（`tools/ci.ps1` 或独立脚本）：

```powershell
# 新增硬编码色为 0；新增 px 只允许出现在 tokens.css 与布局尺寸
Select-String -Path frontend\src\**\*.vue -Pattern '#[0-9a-fA-F]{3,8}\b'
```

**验收**：`grep` 命中数从 55 → 0；页面截图与改前逐像素对比"无意外变化"（只允许统一后的微差）；`vue-tsc` / `vitest` 绿。

### P1 · 卡片与网格节奏（1 天，最影响观感）

**做什么**

1. **统一卡片结构**：`图 + 元信息行 + 操作区`三段式，高度自适应；边框只用 `--border`，hover 用 `--border-strong` + `--shadow-2`。
2. **统一缩略图比例容器**：`aspect-ratio` + `object-fit: cover`，禁止按原图比例跳动（首屏不再重排）。
3. **密度分档**：列表页给出「紧凑 / 标准」两档（`--gap-sm` / `--gap`），默认标准。
4. **选中态**：`outline: 2px solid var(--primary)` + 右上角对勾，替代"变个背景色"。
5. **骨架屏**：首屏与翻页用 `Skeleton` 占位（现有 30 个组件里可新增 1 个通用 `Skeleton.vue`）。

**验收**：连续翻 10 页无布局跳动；同屏一屏内卡片高度一致；hover/选中在 150ms 内可见反馈。

### P2 · 筛选区从"表单风"改"内容驱动"（0.5 天）

**做什么**

1. 分类/体系/标签改成**药丸分段控件**（pill group），当前选中用 `--primary` 实底，未选用 `--panel-2`；
2. 搜索框加图标 + 清除按钮 + `:focus-visible` 环；
3. 筛选结果数就近显示（`共 765 条`），不要只靠分页器暗示。

**验收**：筛选区高度 ≤ 两行；点击任一药丸到列表刷新的感知延迟 < 200ms（视觉反馈先行）。

### P3 · 详情与灯箱（0.5 天）

**做什么**

1. 统一遮罩（`rgb(0 0 0 / .72)`）+ 打开/关闭 180ms 淡入淡出 + `Esc` 关闭；
2. 图片加载中显示进度占位，失败显示"重试"而非裂图；
3. 左右切换加键盘提示（`←/→`），按钮在首/尾置灰。

**验收**：打开/关闭无闪白；键盘全流程可操作。

### P4 · 空状态 / 错误 / 文案（0.5 天）

**做什么**

1. 统一 `EmptyState`（图标 + 一句说明 + 一个下一步动作），覆盖：无数据、无筛选结果、服务离线、无权限；
2. 错误提示统一为"现象 + 原因 + 下一步"三句（现在多处只有一句 `HTTP 500`）；
3. 页脚/关于页放统一的产品名与版本（品牌一致性）。

**验收**：断网/清空数据/筛选无结果三种场景下，页面都不出现裸错误或空白。

### P5 · 动效与一致性巡检（0.5 天）

**做什么**

1. 所有可点元素补 `transition`（颜色/边框/阴影，140–180ms，统一 `--ease`）；
2. 禁止 `transition: all`；
3. 全站巡检：圆角只用 3 档、阴影只用 3 档、字号只用 5 档。

**验收**：抽查 10 个页面，圆角/阴影/字号取值集合不超过各自档位数。

## 3. 批次与顺序

| 批次 | 内容 | 预估 | 备注 |
|---|---|---|---|
| 第 1 批 | P0 令牌 + P1 卡片网格 | 1.5 天 | **观感提升 80% 来自这两项**，先做 |
| 第 2 批 | P2 筛选 + P4 空状态/文案 | 1 天 | 顺手把"廉价感"最多的表单区和错误提示收掉 |
| 第 3 批 | P3 灯箱 + P5 动效巡检 | 1 天 | 收尾，做"精致感" |

每批结束都跑：`npx vue-tsc --noEmit`、`npx vitest run`、`npm run build`，并对 `/gallery` `/prompt` `/editor` 各截一张图存档到 `.screenshots\`。

---

## 4. 明确不做

| 不做 | 原因 |
|---|---|
| 把 Tailwind 引入 atelier 的 Vue 侧 | 两套样式体系混用，比现在更乱；继续 CSS 变量 + scoped |
| 换 UI 框架（Naive → shadcn-vue 等） | 30 个组件全量重写，收益低于成本 |
| 改成亮色主题 | 图片为主的界面暗底更耐看；上游也是暗底 |
| 与 `/ref-web`（React 台）视觉统一 | 两套皮肤已接受；只要求**各自内部一致** |
| 动信息架构（导航/页面划分） | 本次只做表现层 |

---

## 5. 验收方法（可复现，不靠感觉）

1. **截图基线**：改动前对 6 个页面各截一张（1500×950），改后逐张对比；
2. **三条用户路径计时**（脚本化或用秒表）：进画廊→找一张图→打开灯箱；提示词→筛标签→选中；编辑页→选图→提交。改动后不应变慢；
3. **一致性巡检**：`grep` 统计硬编码色/px/字号档位，须单调下降；
4. **可访问性**：正文对比度 ≥ 4.5:1，交互元素 `:focus-visible` 有可见环。

## 6. 风险

| 风险 | 处理 |
|---|---|
| 样式改动碰坏逻辑 | 只改 `<style>` 与 class，不动 `<script>`；每批跑 vitest |
| 令牌替换漏改导致局部变色 | 按文件推进，一批不超过 8 个文件，改完截图对比 |
| 与 gallery-web 的入口混淆 | 本次不涉及；`/ref-web` 独立子路径 |
| 令牌过度抽象 | 只加"用得上"的 4 组刻度，不搞主题切换系统 |
