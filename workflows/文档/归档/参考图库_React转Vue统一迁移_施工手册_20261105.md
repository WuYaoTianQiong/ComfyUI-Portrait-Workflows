- 版本：v1（2026-11-05）

- 目标：把 `/reference` 由「Vue 外壳 + iframe 承载 React `/ref-web`」改为「纯 Vue 实现」，迁移完成后删除 React 子应用，仓库只保留一套前端框架。

## §0 铁律

1. **按本文档顺序推进**，前一个工作包的验收关卡不过，不进入下一个。
2. **后端零改动**（阶段 0–3）。唯一例外是阶段 4 的收尾清理（静态挂载与 `/api/system/status` 字段），且必须单独成批提交。
3. **不修改上游只读目录** `custom_nodes/ai-pose-gallery-zh`。
4. **不把 CharaDB 缓存、IDB 导出图片、上传文件提交进仓库与 `dist`**。
5. **`/api/reference/*` 契约不变**：`libraries`、`items`、`items/{library}/{id}/image`、`recipes`、`sheet`、`uploads`、`fragments` 的参数、分页上限（`page_size` 最大 200）、`kind` 枚举（`thumb|image|depth_thumb|depth`，depth 仅 pose）一律照旧。
6. **第 4 张 `extra` 仍只接受 `library_root/uploads/` 内的文件**。这是安全边界，不因迁移放宽。
7. **不得 kill 运行中的 8656**。验收一律用临时端口（8765/8766）自起自停，报告里标注「需重启才生效」。
8. **实测优先**：任何「已迁移 / 已完成」必须附可复核的命令、退出码与断言计数；未执行项写「未验证」，不得写成通过。

- 目标：`frontend/src/api/reference.ts` + `frontend/src/composables/useReferenceLibrary.ts`，**逐条平移** `referenceAdapter.ts` 的算法语义：
  - `page_size=200` 先取第 1 页，用 `total` 算总页数

  - 总页数上限 200，超限抛明确错误
  - `total` 变化最多补拉一轮增量页
  - 按页序合并、按 `id` 去重保序
  - 任一页失败整体 reject，错误文本带 `library` 与 `page`
  - `null` 字符串归一为 `''`，`tags` 缺失归一为 `[]`，`depthUrl/depthThumbUrl` 保留 `null`
  - 图片 URL 全部走后端端点，禁止直连 `charadb-2fi.pages.dev`，禁止 `/${...}` 二次拼接（历史事故 `//api/...`）

- 验收：

### 14.7 对后续阶段的影响与建议

1. §8 的 **G5「精选/热门标记」与 §7 冻结结论冲突**（React 未实现）。阶段 4.2 写 E2E 时应删除该断言，或改为「不渲染 featured/hot 标记」的反向断言。
