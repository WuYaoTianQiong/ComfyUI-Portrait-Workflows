## 1. 目标与非目标

### 1.1 目标

1. 在**现有「姿势库」标签页**里直接看到两套素材：上游四个体系 + `pose-studio-lite` 的正常/成人两个体系。
2. 搜索、分类、体系、角度、安全模式、合成台选图全部沿用现有交互，不新增页面。
3. 两个上游仓库各自独立更新；本地只维护一个**同步命令**和一份合并读模型。
4. 任何一边更新后，atelier 不重启即可生效（沿用现有 mtime 缓存）。

### 1.2 非目标

- 不把 280 张图复制进 `ai-pose-gallery-zh`，也不生成一份「合并大 JSON」。
- 不为 `pose-studio-lite` 生成深度图；深度模式对无深度条目回退白模。
- 不新增「来源」筛选标签；来源通过体系名区分。
- 不改合成台提交协议：配方仍然提交 `pose_id`，后端解析 `kind=image` 的线稿。

## 3. 架构：来源注册表 + 运行时合并

```
ai-pose-gallery-zh (git, 只读)
  data/pose-zh.json ──┐
  img/ thumbs/       ─┼─→ 来源适配器 A（upstream） ─┐
                      │                              ├─→ pose 合并读模型（1,719 条）─→ 现有「姿势库」标签页
pose-studio-lite (git, 只读)                         │
  meta.json ─────────┼─→ 来源适配器 B（psl）     ────┘
  normal/ adult/     │
  thumbs/            ┘
```

**单一真源原则**：两套素材的事实只存在于各自仓库；atelier 不落盘合并结果，只在内存里拼装。上游 `git pull` 后无需重建；`pose-studio-lite` 更新后只需重建它的 `meta.json`/`thumbs/`。

### 3.1 来源注册表

在 `reference_library.py` 增加一个只服务 `pose` 的来源列表（不是新的对外库）：

| 字段 | upstream | psl |
|---|---|---|
| `key` | `upstream` | `pose-studio-lite` |
| `label` | 原图库 | pose-studio-lite |
| `root` | `settings.reference_root` | `settings.pose_extra_dir` |
| `metadata` | `data/pose-zh.json`（数组） | `meta.json`（`{items:[...]}`） |
| `id_prefix` | 空 | `psl-` |
| `has_depth` | true | false |
| `baseline` | 1,439 | 280 |

`settings.pose_extra_dir` 解析优先级：

1. `ATELIER_POSE_EXTRA_DIR` 显式指定；
2. 自动探测 `<library_root>/../reference-assets/pose-studio-lite`；
3. 自动探测 `<library_root>/../../reference-assets/pose-studio-lite`；
4. 都不存在 → 第二来源禁用，仅加载上游，启动日志说明。

不允许把绝对路径硬编码进代码；没有第二来源时，所有现有行为必须逐字不变。

### 3.2 合并与 ID 规则

- 上游条目保持原 ID（如 `full_single_P001_front`）。
- PSL 条目统一前缀：`psl-D001`、`psl-U026`。
- 分组键仍是 `体系|姿势编号`；PSL 的体系写作：
  - `pose-studio-lite・正常姿势`
  - `pose-studio-lite・成人风格`
- PSL 的 `姿势编号` 保留原编号（`D001`），`角度` 取 `angle_zh`（正面/斜侧/侧面…）。
- 合并顺序：upstream 在前，PSL 在后；同体系内按现有前端 `localeCompare` 排序。
- `PREFERRED_POSE_LINE_ORDER` 不新增项；未知体系自然排在四个现有体系之后。

### 3.3 记录映射（PSL → 现有 DTO）

| DTO 字段 | PSL 来源 |
|---|---|
| `id` | `psl-` + `meta.id` |
| `name` | `meta.name` |
| `number` | `meta.id` |
| `group` | `pose-studio-lite・` + `meta.group` |
| `facet` | `meta.facet`（站立/坐姿/躺姿/跪姿/…，保留原分类） |
| `angle` | `meta.angle_zh` |
| `tags` | `meta.tags` |
| `nsfw` | `meta.nsfw`（`adult/` 恒 true） |
| `thumb_url` / `image_url` | `/api/reference/items/pose/{psl-id}/image?kind=thumb|image` |
| `depth_url` / `depth_thumb_url` | 恒 `null` |
| `search_text` | `meta.search` + 来源名 + 分类 + 系列 |
| 内部字段 | `_root`=PSL 根、`_thumb_rel`/`_image_rel`=meta 相对路径、`_has_depth`=false、`_source`=`pose-studio-lite` |

### 3.4 图片解析

- `_safe_image_path(rel, root)` 增加显式 `root` 参数；默认仍是 `reference_root()`。
- `resolve_image()` 按条目的 `_root` 解析；越界校验必须针对该来源根，不能只校验上游根。
- `kind=depth|depth_thumb`：仅 `_has_depth=true` 的条目可解析；PSL 一律 404（前端已回退，不会主动请求）。
- 缩略图/原图缺失按现有语义 404，不回退到另一来源。

### 3.5 深度模式回退

- `poseThumbnailUrl(item, true)`：若 `depthThumbUrl`/`depthUrl` 都为空 → 返回 `kind=thumb`。
- `posePreviewUrl(item, true)`：同上 → 返回 `kind=image`。
- 合成台槽位、灯箱、画廊卡片共用这两个函数，因此只改一处。
- `useReferenceRecipeDraft` 的 `addPose/setPose/togglePose/setPoseMode`：无深度条目强制 `useDepth=false`，避免「深度模式选中」的 UI 状态与实际取图不一致。
- `ReferencePosesTab` 的选中判断改为「全局深度模式 && 条目支持深度」，避免 PSL 卡片在深度模式下无法显示选中态。

### 3.6 单角度分组的 UI

PSL 大多数姿势只有 1 个角度；现有 `groupCards` 固定渲染 5 个角度格，会留 4 个空占位。
调整：当分组 `order.length === 1` 时只渲染该角度格；2–5 个角度保持现有 5 格布局不变（避免影响上游 4/3 角度的既有观感）。

### 3.7 NSFW 与安全模式

- PSL `adult/` 173 条 `nsfw=true`。
- `poseSystemSummaries` 会把 `pose-studio-lite・成人风格` 整条标成 18+；安全模式下整条体系隐藏。
- `ATELIER_REFERENCE_ALLOW_NSFW=1` 时正常显示；与上游现有口径一致。
- 不把成人条目混入正常体系，避免安全模式失效。

### 3.8 统计与基线

- `library_stats()["pose"].total` = 两来源之和（1,719）。
- 不再用单一 1,439 基线检查合并结果；改为**逐来源**检查：
  - upstream 偏离 1,439 ±5% → warning；
  - psl 偏离 280 ±5% → warning。
- 启动日志输出：`姿势库合并：upstream=1439，pose-studio-lite=280`。
- `available`：任一来源元数据存在即为 true。
- 可选在 stats 里增加 `sources` 明细（key/label/total/available/commit）；前端不依赖，坏字段不阻塞。

## 4. 同步：一条命令，不是两次

新增 `脚本/atelier/tools/sync_pose_sources.py`。

### 4.1 流程

1. 检查两个仓库工作区是否干净（`git status --porcelain`）；脏则拒绝，除非 `--allow-dirty`。
2. `git -C ai-pose-gallery-zh pull --ff-only`
3. `git -C pose-studio-lite pull --ff-only`
4. 重新解析 `pose-studio-lite/index.html` + `names.en.js`：
   - 重建 `meta.json`
   - 增量重建 `thumbs/`（源文件比缩略图新才重建）
5. 校验：
   - PSL 280 条、ID 唯一、每条原图/缩略图存在、中英提示词非空；
   - upstream `pose-zh.json` 可解析，条数与基线偏差在容忍范围；
   - 两个 commit 记录到 `reference-assets/sync-state.json`（不写入任一上游仓库）。
6. 失败即非零退出，保留上一版 `meta.json`；atelier 继续服务旧数据。

### 4.2 模式

| 参数 | 行为 |
|---|---|
| 默认 | 两边 pull + 重建 PSL 索引 + 校验 |
| `--check` | 只校验，不 pull、不重建 |
| `--no-pull` | 不 pull，只重建 PSL 索引 + 校验 |
| `--skip-upstream` / `--skip-psl` | 只处理单边 |
| `--allow-dirty` | 允许工作区脏（不建议；用于人工修图后重建） |

### 4.3 为什么不自动

- 不在应用启动时自动 `git pull`：网络失败/上游改坏会拖慢启动并让图库不可用。
- 不做后台定时强拉；需要时手动一条命令，或外部计划任务跑 `--check` 提醒。
- 两个仓库各自保留 git 历史，回滚用 `git -C ... checkout <commit>`；`sync-state.json` 记录上次成功版本。
