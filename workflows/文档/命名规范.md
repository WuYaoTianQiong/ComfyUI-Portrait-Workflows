## 0. 为什么改名

现在的名字描述的是一个**已经被推翻的产品形态**。

`prompt_browser` 只覆盖"浏览提示词"这一小块，而项目现在的实际能力面是四条链：

1. **资产库**：提示词、结构化碎片（`【类型】`）、组合模板、标签、分类树
2. **生产**：ComfyUI 工作流参数注入、单次/批量/随机出图、换脸与遮罩编辑
3. **归档**：图库（含软删、缺图自愈、标签/分类继承）
4. **调度**：任务状态机 + 单写者线程 + SSE 推送

`v4` 更是一个没有信息的后缀：它同时被用来指"应用第 4 代"（`main.py:73-75`）、"schema 迁移第 4 版"（`models.py:566` 注释 `v4.x 基线`，实际迁移编号却是 `v1/v2/v3`）、"文档里的迭代批次"（`models.py:395-401` 注释 `v4.0/v4.1/v4.2`）。**同一个 `v` 指三件事**，这是最先要消灭的东西。

`atelier`（画室/工坊）的选择理由：一个词覆盖"素材 → 生产 → 归档"整条链，不带能力降级词、不带版本号，ASCII 且可直接作 Python 包名，中文可对应「画室」。

## 2. 领域术语表（核心，唯一真源）

这是本规范最重要的一节。**代码读起来别扭，根源不是文件名叫什么，而是同一实体有 4 个名字。**

### 2.1 一级概念

| 概念 | 现在的叫法（同一实体） | 规范叫法 | 说明 |
|---|---|---|---|
| 一张出图记录 | `GenHistory`(类) / `gen_history`(表) / `history`(路由) / `GalleryView`(前端视图) / "画廊" / `item`(局部变量) | **`Image`** | "历史/画廊"是 UI 概念，不是数据概念。**schema 已经这么叫了**：`image_tags`、`image_categories` 里的外键就叫 `image`（`models.py:163,175`），只有模型类名还叫 `GenHistory` |
| 图库视图 | `GalleryView.vue` / `/gallery` | **Gallery** | 仅前端视图名；后端不得出现 `gallery` 字样 |
| 提示词 | `Prompt` | **Prompt** | 保持不变 |
| 标签 | `Tag` / `Prompt.tags`(文本字段) / `taxonomy`(模块名) | **Tag** | `taxonomy` 指"标签体系"，不是"标签"，且与 `models.inherit_prompt_taxonomy` 语义重叠；服务模块改名 `tagging.py` |
| 碎片 | `Fragment`(碎片库) / `TemplateFragment`(模板槽位) / `segment`(前端) | **Fragment** / **Slot** | 模板里的槽位不是碎片 → `TemplateSlot` |
| 组合 | `composer`(功能) / `composition`(服务模块) / "组合器" | **Composer**（功能/页面）· **Composition**（组合结果） | 服务模块 `composition.py` → **`fragment_syntax.py`**（它做的是 `【类型】` 语法的解析/渲染/校验；不用 `naming.py`，因为「naming」在中文语境里极易被读成「文件命名」） |
| 任务 | `GenJob` / `gen_jobs` / `items`(JSON 列) | **Job**；`items` → **`steps`** | `items` 里存的是"每张图的子任务"，叫 steps 才说得清 |
| 出图动作 | `run` / `generate` / `push_prompt` / `batch_generate` / 中文"跑图、投喂" | 单次 **run**，批量 **batch** | `push`/"投喂" 只作注释用语，不进标识符 |
| 缺图 | `missing_since` / `cleanup_missing` / "墓碑" | **missing** | 文件不存在，可自愈 |
| 软删除 | `is_deleted` / `tombstone` / "墓碑" | **trash** | 用户主动删。与 `missing` **严格区分**（`models.py:123-125` 已有正确注释，术语需统一到代码名） |
| 收藏 | 提示词 `is_favorite`(`models.py:72`) vs 图片 `favorite`(`models.py:116`) | **`is_favorite`** | 图片侧用 ORM 别名对齐，见 §7.2 |

### 2.2 术语使用规则

- 一个概念**只能有一个词**；同义词只允许出现在"迁移说明/兼容注释"里。
- UI 文案与代码标识符**必须对应**：页面叫"画廊"，后端就叫 `images`；页面叫"图像编辑"，组件就叫 `EditorView`（P2c 已消除 `FaceswapView` ↔ "图像编辑" 这种分裂）。
- 严禁用 `item`、`data`、`info`、`obj` 作实体名。`item` 只在循环变量里局部使用。

### 3.2 结构硬规则

1. **顶层不得有通用名模块**（P2b 已达成）。`config.py / models.py / schemas.py` 收进 `app/` 包，根目录只留 `main.py` 启动壳；`shared.py` / `state.py` 已分别并入 `services/batch_control.py` 与 `services/composition → fragment_syntax`。
2. ** routers 不写业务**：SQL、文件 IO、ComfyUI 调用一律下沉 `services/`。
3. **一个模块名必须是名词**，禁止 `helpers / utils / common / misc / shared / base / state`。这些名字的含义是"我不知道放哪"。
4. **一个路由文件对应一个资源**。`comfyui.py` 曾同时承载全局图片代理（`/api/image`、`/api/thumbnail`），语义越界 → 已拆到 `media.py`（P2b-2，`2927e08`）。
5. **开发用页面不进主导航**。`DesignView.vue`（设计令牌预览）只在 `/dev/design`，顶栏无入口（P2c 已落地）。
6. **运行时产物一律不进版本库**，也不进项目根：`_e2e_shot.png`、`_pb_out.log`、`_pb_err.log`、`_e2e_server.log`、`_smoke_server.log`、`logs/run_*.json`。

## 4. 文件命名

| 类型 | 规则 | 示例 |
|---|---|---|
| Python 模块 | 小写 + 下划线，**名词**，单数 | `image_store.py`、`job_state.py` |
| Python 测试 | `test_<被测模块>.py` | `test_image_store.py` |
| 前端视图 | `PascalCase` + `View` 后缀，且与路由段、导航文案三者同名 | `GalleryView.vue` ↔ `/gallery` ↔ "画廊" |
| 前端组件 | `PascalCase`，**不带** `Panel/Modal/Box` 之外的模糊后缀 | `MaskEditorModal.vue` |
| 前端 composable | `useXxx.ts`，一个文件一个 composable | `useWorkflowCaps.ts` |
| 前端纯函数 | `camelCase.ts`，放在 `utils/`，**不得与 composable 重名** | `format.ts` |

## 5. Python 符号命名

### 5.1 函数必须以动词开头（动词表封闭）

| 动词 | 语义 | 返回 |
|---|---|---|
| `get_` | 取单条，找不到返回 None | 对象/None |
| `list_` | 取多条 | list |
| `create_` | 新建 | 新对象 |
| `update_` | 局部更新 | 更新后对象 |
| `delete_` | 硬删 | bool/计数 |
| `trash_` / `restore_` | 软删/恢复 | bool |
| `set_` | 幂等设值 | 新值 |
| `toggle_` | 翻转，**必须返回新值** | 新值 |
| `sync_` / `backfill_` / `scan_` | 全量对齐/补历史/巡检 | dict 统计 |
| `run_` / `cancel_` | 触发/取消外部执行 | job/id |
| `export_` / `import_` | 序列化进出 | 数据 |

禁止裸名词函数（`favorite()`、`inherit()`、`position()`）。禁止 `handle_/process_/do_/manage_`——它们不说明做了什么。

### 5.2 同名不同义零容忍

现状反例：`routers/prompts.py:345` 与 `routers/history.py:820` 各有一个 `toggle_favorite`，一个改提示词、一个改图片，调用方看名字无法判断。

规范：**动作函数必须带主语** → `set_prompt_favorite(...)` / `set_image_favorite(...)`；若保留 `toggle_` 语义则返回 `{id, is_favorite}`。

### 5.3 其他硬规则

1. **禁止 1-2 字母缩写**。`from models import GenHistory as Gh`（`routers/history.py:14`）→ 直接 `Image`；`rid`（`main.py:92`）→ `request_id`。
2. **布尔量一律 `is_/has_/should_` 前缀**，DB 列同步见 §7.2。
3. **私有函数 `_` 前缀且名字要有语义**（`_meta`/`_prev` 这类无可读性，须改为 `_cached_meta`/`_previous_status`）。
4. **单复数**：函数名用单数（`get_image`），集合变量用复数（`images`），模块名单数（`image_store`）。
5. **端点函数名 `动词_资源`**：`list_images`、`import_prompts`、`run_composer`。
6. **异常**：自定义异常以 `Error` 结尾，放在 `app/errors.py`；禁止只 `except Exception: pass`。
7. **与第三方库撞名时，让领域名优先**：模型类叫 `Image` 后，凡需要 PIL 的模块一律写
   `from PIL import Image as PILImage`（含函数内局部导入，注意缩进）。反过来把领域类改叫
   `ImageRecord` 之类的做法，只会让每个调用点都变啰嗦。

```
/api/{复数资源}[/{id}][/{子资源}][/{子资源 id}]
```

### 6.2 现行裸动词端点全部收编（P3 已落地，2026-11-01）

| 旧 | 新 | 备注 |
|---|---|---|
| `GET /api/status` | `GET /api/system/status` | |
| `GET /api/config` | `GET /api/system/config` | |
| `GET /api/stats` | `GET /api/system/stats` | 原 `routers/stats.py` 并入 `system.py` |
| `POST /api/run` | `POST /api/runs` | |
| `POST /api/run_text` | `POST /api/runs/text` | **补做**：原表漏列，只改 `run` 会留下两套命名 |
| `POST /api/batch_generate` | `POST /api/runs/batch` | |
| `GET /api/progress` | `GET /api/jobs/progress` | 必须注册在 `/api/jobs/{id}` 之前 |
| `POST /api/batch_stop` | `POST /api/jobs/stop_all` | |
| `GET/POST /api/history_sync` | `GET/POST /api/images/sync` | |
| `GET/POST /api/history` | `GET/POST /api/images` | `/facets`、`/ids`、`/cleanup_missing`、`/batch_delete`、`/{id}/*` 全部跟随 |
| `GET /api/image`、`GET /api/thumbnail` | `GET /api/media/image`、`GET /api/media/thumbnail` | 含 `/media/thumbnail/clear` |

**仍然"不是复数资源"但刻意没动的端点**（不属 §6.2 表，改动面与收益不成比例）：

| 端点 | 未动的理由 |
|---|---|
| `GET /api/validate_workflow` | 语义是"对某个路径做校验"，落成 `/api/workflows/validate?path=` 更规范，但它与 `/api/workflows` 同族，应连 `/api/workflows/{id}/caps` 一起设计 |
| `GET /api/generate_missing/{count,list}`、`POST /api/generate_missing` | 实为"缺图补跑"，规范形应是 `/api/runs/missing*`；涉及前端 `MissingImageRunPanel` 与 3 处测试，单列一批 |
| `POST /api/composer/{run,batch_random_run}` | `composer` 是功能名不是资源，但 `/api/composer/fragments` 同时是"取碎片候选"的数据源，改名要连碎片资源一起理，转出 |

### 6.3 批量动作

统一 `POST /api/{资源}/batch_<动词>`：`batch_delete`、`batch_favorite`、`batch_import`、`batch_tag`。**保留下划线**（现有 6 处已一致），不为了追连字符风格而制造第二套写法——**一致性 > 教条**。

### 6.4 过渡策略

改路由**必须留 308 别名一个版本**，因为：① E2E（`tests/e2e/run_e2e.py`）与契约测试（`tests/test_contract.py`，705 行）硬编码路径；② 浏览器书签与前端构建产物可能仍是旧路径；③ 硬刷新前用户手上是旧页面。

别名实现集中在 `app/routers/legacy.py`（P3 已落地），三条硬约束：

1. **必须是 308**（不是 301/302）：308 保留方法与请求体，浏览器的 `fetch` 会自动把 POST 重发到新地址；301/302 会把 POST 降级成 GET。
2. **Location 必须带 `/api` 前缀**：别名 router 以 `prefix="/api"` 挂载，但 Location 是绝对路径，漏了 `/api` 会跳到 `/images/...` 这种非 API 路径 —— 被 SPA catch-all 接住，返回 `index.html` + 200，**看起来没坏、实际什么都没发生**（这是本轮踩过的真实坑，已用 `tests/test_legacy_aliases.py` 锁死）。
3. **必须在 `main.py` 里晚于全部正式路由注册**：注册在前面会抢走新路径的请求。

计数与观察：每个旧路径首次被访问打一条 `WARNING 旧路径别名首次访问`，之后每次打 `INFO ...（该路径累计 N 次）`。退役判定 = 扫日志里所有「首次访问」行 —— 一个版本内没有新增行，就把 `legacy.py` 整份删除。

### 6.5 版本前缀

**不加 `/api/v1`**。单机内部工具、无外部调用方，加版本前缀只增加维护面。若将来要对外开放，再整体迁移。

## 7. 数据库规范

### 7.1 表名：**不改**

`gen_history` / `gen_jobs` / `prompt_tags` / `image_tags` 等已被 ComfyUI 侧进程、`tools/backup_db.py`、`文档/` 多处引用，且 `gen_history` 上有部分唯一索引（`models.py:129-133`）与 6 个显式索引（`models.py:553-559`）。**表名与列名的物理迁移风险远大于命名收益** —— 在 ORM 层对齐语义即可。

### 7.2 类名/属性名：对齐，但不动库

```python
class Image(BaseModel):                       # 原 GenHistory
    is_favorite = BooleanField(column_name="favorite", default=False)   # 列名不变，代码名统一
    class Meta:
        table_name = "gen_history"            # 表名不变
```

这样"代码里全是 `is_favorite`、库里还是 `favorite`"，零迁移、零风险。

### 7.3 迁移命名

**过程坑（值得记）**

- **308 的 Location 必须带 `/api`**：别名 router 以 `prefix="/api"` 挂载，但 `RedirectResponse` 的 Location 是绝对路径。第一版漏了前缀，于是 `/api/history/html` 跳到 `/images/html` → 不是 `/api/` 开头 → 被 SPA catch-all 接住 → 返回 `index.html` + **200**。表现是"旧路径没坏，但什么都没发生"，契约测试当场抓到（断言该路径应为 404/405/422，实际 200）。现已由 `tests/test_legacy_aliases.py` 锁死「Location 以 `/api` 开头 + 保留查询串 + 子路径跟随」。
- **批量替换脚本必须带后缀断言**：`/api/run` 是 `/api/run_text`、`/api/runs/batch` 的前缀，必须用 `(?![A-Za-z0-9_])`；反过来 `favorite: boolean` 是 `is_favorite: boolean` 的后缀，用朴素替换会把提示词侧的 `is_favorite` 变成 `is_is_favorite`（本轮踩到并修正）。
- **CRLF 会让「精确多行匹配」静默失配**：`types.ts` 的多行替换因 `\n` vs `\r\n` 没生效，而单行的 `PromptListPage` 生效了 —— 同一个脚本"改了一半"最难查。改代码一律用正则 `\r?\n`，别用字面量换行。
- **项目路径含中文（`脚本`）+ Windows + `shell=True`**：`subprocess` 会把中文参数按 URL 编码传给 node，`openapi-typescript` 直接 ENOENT。解法是给子进程传**相对 cwd 的 ASCII 路径**。
- **`Required<T>` 不会传播到嵌套**：`Required<Schemas['HistoryListResponse']>` 只让 `items` 变成必填，`items` 的元素类型仍引用 schema 里原始的 `HistoryItem`。分页信封要写成 `Omit<Required<...>, 'items'> & { items: HistoryItem[] }`。
