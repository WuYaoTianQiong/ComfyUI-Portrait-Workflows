# Atelier 第二轮全局收敛 · 施工计划（2026-11-07）

> 分支：`refactor/b0-safety`
> 前置阅读：[Atelier_全局收敛_计划_20261107.md](./Atelier_全局收敛_计划_20261107.md)、[Atelier_交接_20261107.md](./Atelier_交接_20261107.md)
> 本文用途：记录第二轮“全局最优”收敛的决策、批次边界、验收与回滚方式。每完成一批，更新勾选与检查点。

---

## 0. 本轮拍板结论（2026-11-07）

1. **先 P0 正确性与安全**，再身份/状态/产品收敛；
2. **允许小改数据模型 + 迁移**（加列、加表、加索引，兼容旧数据；不删除既有列）；
3. **本轮收敛为“一 job 多 item”**，不再保留“每组一 job”作为长期形态；
4. **发型升为正式第 4 槽**，纳入槽位协议，不再靠工作流标题正则特判。

---

## 1. 为什么不再按“功能”收敛

第一轮按功能波浪处理了主干重复实现。第二轮审计发现，剩余问题几乎都是跨域不变量失守：

| 不变量 | 当前失守点 |
|---|---|
| 身份 | workflow 靠文件名；asset 有 4 套寻址；tag 靠文本；category 名/key 混用 |
| 状态 | item `status` 与 `submit_state` 双轨；sync/queue 两套失败语义；取消/重试竞态 |
| 文本 | `【】` 三种切块；`•` 前后端各解析一遍；全仓 7 处拼装器 |
| 生命周期 | 软删被扫描复活；远端缓存/上传无 GC；读路径写盘；缩略图键会串图 |
| 契约 | `openapi.d.ts` 只当字典用；`ApiError` 无生产调用方；CI 缺依赖仍 PASS |

**本轮原则**：局部实现为不变量让步；不再为单个功能新增旁路。

## 3. P0-A · 恢复与验收

### A1 启动先备份再迁移

- 现状：`app/main.py` 先 `init_db()`（执行迁移），再 `run_startup_maintenance()`（备份）。v6 的 `DROP TABLE fragments` 已证明顺序错误。
- 方案：
  1. `app/services/migrations.py` 增加只读 `pending_versions(db_path)`：库不存在返回 `[]`；`schema_version` 不存在按 v0 处理。
  2. `app/services/maintenance.py` 增加 `backup_before_migrations()`：仅生产库、库存在且有 pending 时，打 `pre_vN` 备份。
  3. `run_startup_maintenance(backup: bool = True)`；lifespan 先 `backup_before_migrations()`，再 `init_db()`，再 `run_startup_maintenance(backup=pre_backup is None)`。
- 验收：在库副本上造 pending v8，断言迁移前备份存在；迁移失败可从备份恢复；无 pending 时仍保留原启动备份。
- 回滚：还原 `main.py` / `migrations.py` / `maintenance.py`，备份文件不影响运行。

### A2 CI 不再假绿

- 现状：`tools/ci.ps1` 在 `frontend/node_modules` 缺失时跳过第 3–7 关，最后仍打印 `CI PASS`。
- 方案：缺依赖直接 `FAILED` + `exit 1`；E2E 的 Playwright 缺失仍允许 SKIP，但打印 skipped 数并计入摘要。
- 验收：临时改名 `frontend/node_modules`，CI 必须失败。

### A3 资产型测试隔离

- 现状：`tests/conftest.py` 隔离了 DB/缩略图/ComfyUI 根，但没有隔离 `library_root`；部分测试依赖本机磁盘，缺失时静默 skip 或硬失败。
- 方案：
  1. conftest 设置 `ATELIER_LIBRARY_ROOT` 到临时目录，并复制 `tests/fixtures/workflows/` 的最小工作流样本；
  2. 依赖真实资产的测试改用 fixture；真实资产只做“若存在则校验”的额外检查；
  3. 禁止静默 `pytest.skip`，skip 必须带原因并计入 CI 摘要。
- 验收：把工作流目录临时移走，pytest 仍全绿；CI 结果与机器磁盘无关。
- 回滚：还原 conftest 与相关测试；不影响生产代码。

### A4 工具脚本失真

- `tools/run_prompts.py` 仍按旧库根路径找文件，当前必 FileNotFound；
- `tools/audit_workflows.py` 只扫库根 `*.json`，当前为 0 个，永远 PASS。
- 方案：统一从 `workflow_catalog` 取目录；审计覆盖 `通用工作流/` 与 `图库专用工作流/`；`run_prompts` 兼容新目录并保留旧布局回退。
- 关于 `gen_api_types.py` 换行：仓库 `core.autocrlf=true`，`openapi.json` 工作区是 CRLF；强行改 LF 会让 CI 的前后哈希比对必然假红，因此**不改**，交给 git 行尾转换处理。
- 验收：三个工具在干净工作区可重复运行且结果稳定。

## 4. P0-B · 任务正确性

### B1 sync 提交失败计数

- 现状：`app/services/generation.py` 的 sync 分支在 push 失败时只把 job 置 error，items 没有 status，`error_count=0`；前端据此不显示重试。
- 方案：失败时先把 items 标为 error，再 `update_job_items`；新增回归测试断言 `error_count == len(items)` 且前端可重试。
- 回滚：还原该分支。

### B2 sync 多 index 拒绝

- 现状：sync 只推 `indexes[0]`、只回写第一条，传多个会静默丢条目。
- 方案：P2 支持一 job 多 item 前，`len(indexes) > 1` 直接 400，并给出明确错误。
- 验收：传两个 index 返回 400，不建 job。

### B3 取消终态保护

- 现状：`app/services/job_state.py::cancel_job` 对 done 任务取消会把 job 改 stopped，并把 error 条目改成 cancelled。
- 方案：job 已终态直接返回失败；只改 pending/running；保留原 error 文案；新增 done/error/cancelled 三种输入的测试。
- 回滚：还原 `cancel_job`。

### B4 取消与 push 竞态

- 现状：cancel 时 pid 尚未落库，cancel 认为无可 interrupt；push 成功后 item 已是终态，写不进去，ComfyUI 继续跑。
- 方案：push 返回后再次读取 item；若已 cancelled，立即 interrupt / 删除该 pid 的队列项，不再标 running。
- 验收：用假 ComfyUI 客户端模拟“cancel 发生在 push 期间”，断言最终调用 interrupt 且 item 不被改回 running。

### B5 seed 与重试参数快照

- `app/routers/composer.py` 的 `random.randint(0, 2**32-1)` 可能取 0，而 `resolve_seed` 把 0 当“未指定”重掷；改为 `1..2**32-1`。
- composer 随机的 `prompt_params` 缺 steps/cfg/sampler，重试会按默认值注入；把实际生效参数快照进 item。
- 验收：seed 永不为 0；重试参数与原提交一致。

### B6 空响应处理

- `frontend/src/api/client.ts` 无条件 `resp.json()`，204/空体抛 SyntaxError，绕过 `ApiError`。
- 方案：按 `content-length` / 空文本容错，返回 `null`；补单测。

## 5. P0-C · 文件一致性

### C1 软删不复活

- 现状：磁盘扫描只把 `is_deleted=0` 当已存在（`app/routers/images.py`），软删后文件仍在，下一轮扫描又入库；墓碑回收删行不删文件，也会复活。
- 方案：
  1. 新增 `file_tombstones(asset_key PRIMARY KEY, deleted_at, reason)`；
  2. 删除（单条/批量）写入墓碑；扫描加载墓碑集合并跳过；
  3. 墓碑回收只删 `gen_history` 行，不删墓碑；新增显式“恢复”接口清墓碑；
  4. 物理删除文件时也保留墓碑，避免同名文件再次出现时被自动收编。
- 验收：软删 → 扫描 → 仍不可见；恢复 → 扫描 → 重新可见；墓碑回收后仍不复活。
- 回滚：删除墓碑表引用；旧行为恢复，但需接受复活风险。

### C2 缩略图键与清理

- 现状：`app/services/thumbnail.py` 用下划线拼前缀，`a_b/c` 与 `a/b_c` 会互删；缓存键不含处理版本。
- 方案：对 `(filename, subfolder, type)` 做哈希作为文件名前缀；键加入 `THUMB_VERSION`；`clear_thumbnails_for` 精确删该哈希前缀。
- 验收：构造上述碰撞路径，删除 A 不影响 B；改版本后旧缓存不命中。

### C3 媒体只放行图片

- 现状：`app/services/paths.py::is_safe_image_ref` 只校验路径，不校验扩展名；`/api/media/image` 可读 output 下任意文件。
- 方案：`is_safe_image_ref` 增加 `IMAGE_EXTENSIONS` 白名单；补充 `.json`/无扩展名返回 400 的测试。
- 回滚：去掉扩展名校验。

### C4 清空缩略图不再 rmtree

- 现状：`/api/media/thumbnail/clear` 直接 `rmtree` 整个缩略图目录，会连带删除浏览器缓存。
- 方案：只删 `.webp` 文件或按清单删；保留目录与其它缓存。

## 6. P1 · 身份与真源

1. **workflow manifest + sha256**
   - 新增工作流清单（建议 `<库>/工作流清单.json` 或每目录一份）；
   - 字段：`id, file, sha256, version, status(active|archived|blocked), dir_scope, slots, caps, quality_tiers, default_ratio, notes`；
   - 文件名降级为显示标签；Job/Item 存 `workflow_id + hash`，旧 `workflow_path` 兼容读取。
2. **quality 键统一**
   - 对外与落库统一 `0.75x…2.0x`；旧 `2K…12K` 只做读取别名；
   - v8 迁移归一 `gen_jobs.quality` 与 `extra.atelier.quality_tiers`；
   - 前端 localStorage 兼容读。
3. **标签/分类单轨**
   - `entity_tags` 为唯一真源；`prompts.tags` 降为只读缓存（本轮不删列）；
   - 分类身份 = id + `system_key`；禁止按名字匹配系统分类。
4. **Prompt IR**
   - 唯一解析器输出 `PromptDoc{segments, negative_terms, order}`；
   - 编译只做 IR→IR，渲染只做 IR→目标文本；
   - 第一版影子运行：新旧解析只报告差异，不切写入。
5. **AssetStore**
   - `AssetRef{Comfy|Library|Upload|Remote|Derived}` + 统一 `stat/open/thumbnail/exists/delete/gc`；
   - media / reference / sheet / editor 全部经它。
6. **幂等唯一索引**
   - `gen_jobs` 增加 `idempotency_key` + `(scope, key)` 唯一索引；
   - 前端提交补 `X-Idempotency-Key`。

## 7. P2 · 状态与入口统一

1. `SubmitSpec` 唯一入口：校验、幂等、建 job、子目录、入队、事件都在服务内完成；
2. item 级 `workflow/quality/orientation` 下沉，重试按 item 重建；
3. 单状态机：`queued→submitted→running→done|failed|cancelled`，删除 `submit_state` 双轨；
4. 单事件流：`/api/jobs/events?since=seq`，支持 `Last-Event-ID` 重放；
5. 前端：补齐 domain api，单例 job tracker，统一结果卡；`ApiError` 进入生产路径。

**验收**：批量/合成台/编辑/重试共享同一状态语义；取消可下探到 item；断线重连不丢事件。

## 8. P3 · 产品与生命周期

1. **发型正式第 4 槽**
   - `SlotDescriptor{key, media_kind, multi, mode, source, capabilities, label}` 驱动草稿、矩阵、校验、提交、结果；
   - 工作流 manifest 声明 slots，混合工作流按能力启用/禁用；
   - 删除 `图4/发型` 标题正则与前端散落特判。
2. **缓存/上传 GC**
   - 缩略图、远端缓存、上传图、临时输入图都有 retention 与清单；
   - 只删未被引用的派生/上传；删除前可 dry-run。
3. **历史工作流归档**
   - `历史工作流/` 52 个进入 manifest `archived`，或整体移出工作流库；
   - 清理空目录与临时状态目录。
4. **可选：一批一 job**
   - 在 P2 一 job 多 item 稳定后，再做后端批量配方聚合。

## 9. 验收与回滚

每批结束：

```powershell
cd 脚本/atelier
python -m pytest -q
cd frontend
npx vue-tsc --noEmit
npx vitest run
npx vite build
cd ..
python tools/smoke.py
python tests/e2e/run_e2e.py
```

- 任何 DB 变更前：`python tools/backup_db.py --tag before_<batch>`；
- 迁移只追加版本，不改旧版本号；
- 一次一批提交；改名与改行为分开；
- P0-A 额外做“迁移前备份恢复演练”；
- P0-C 额外做“软删后扫描不复活”的回归。

## 10. 本轮明确不做

- 不合并 Composer 与 Studio 的交互范式；
- 不引入 axios / 新状态库；
- 不做 `prompts.tags` 的删列（只降为只读缓存）；
- 不迁移参考图库素材本体；
- 不改 `启动.bat` 的 18+ 总闸行为；
- 不在 P0 阶段做批量 job 聚合。
