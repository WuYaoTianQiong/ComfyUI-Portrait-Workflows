## 一、改了什么

### 1. 状态从"读接口顺手写库"改成"唯一写者推进"

| 之前 | 现在 |
|---|---|
| `GET /api/jobs/{id}` 每次调用都拉 ComfyUI `/queue` + `/history?500`、写 `gen_jobs.items`、插 `gen_history` | `GET` 只读 DB，不访问 ComfyUI、不写库 |
| 前端 1 Hz + 后端 5 s 监控 + 第二个 tab 三方并发 read-modify-write（日志里同一 pid 写了 12 次） | `services/job_state.writer_loop` 单线程每秒推进，所有任务写入在同一把锁内 |
| 监控循环是 `async def` 里跑同步 HTTP/DB，ComfyUI 慢会阻塞事件循环 | 普通守护线程，事件循环不再被阻塞 |
| 无法判定时写 `unknown`，落库后再无代码重选（旧库卡了 56 个 item） | `unknown` 永不落库，保留原状态等下一轮 |

### 2. 取消归属到单个任务

- 旧：`interrupt()` + `clear_queue()` 全局清队列 —— 取消 A 会杀掉 B 正在跑的那张。
- 新：只对属于本任务的 pid 调 `interrupt()`，并用 `POST /queue {"delete": [...]}` 定向删除本任务待跑项。
- 新增 `delete_queue_items()`；`/api/batch_stop` 语义变为"取消所有进行中的任务"。

### 3. SQLite 并发

- `journal_mode=WAL` + `synchronous=NORMAL` + `busy_timeout=5000`。
- 备份/复制数据库时必须连带 `-wal`、`-shm`；`verify_smoke.py` 已同步处理，`.gitignore` 已忽略这两个文件。

### 4. SSE + 前端 JobStore

- 新端点 `GET /api/jobs/events?ids=1,2`：首帧 `snapshot`，之后 `job` 事件；15s 一次 `: ping`；单 id 订阅在终态后关流。
- 前端只有一个 `EventSource`，所有活跃任务复用它；3 秒无事件或浏览器不支持时自动降级回原来的 1s 轮询（`localStorage.pbSse = "0"` 或 `?sse=0` 可强制关闭）。
- 终态处理只有一份 `_finalizeJob()`，SSE 与轮询共用；失败/取消也会给 toast，不再静默消失。

### 5. 提交入口统一

`window.submitTask({endpoint, payload, title, errorPrefix, timeout, track, onJob})`：
离线拦截 → 占位进度（HUD）→ POST → `trackJob`。

已迁移全部 8 条路径：单图、批量、变体、补全缺图、组合跑图、组合批量随机、试跑、换脸、画廊处理。
其中试跑用 `onJob` 先注册完成回调；换脸用 `track=false` 继续走自己的进度面板。

### 6. 提交宽限期（本轮发现并修掉的新隐患）

批量提交时 `create_job` 先落库、`push` 完才写回 `prompt_id`。写者每秒刷新，会把"还没有 pid"误判为失败。
现在按 `created_at` 给 300 秒宽限期；注意 SQLite 的 `CURRENT_TIMESTAMP` 是 UTC，必须用 UTC 比较，否则宽限期凭空失效（本轮实际踩到并修正）。
