## 2. 批次 0：安全与正确性

目标：先修“会读错/删错/算错”的问题，不动 UI 结构。

### B0-1 路径安全与 CORS

- `app/services/paths.py`
  - 新增相对路径校验：拒绝绝对路径、盘符、`..`、`.`、空段；
  - `resolve_image_path` 在拼接前校验 `filename` 与 `subfolder`；
  - 新增 `resolve_browser_image(path)`：只允许图片扩展名，返回真实可读文件或 `None`。
- `app/routers/media.py`
  - `/api/media/image`、`/api/media/thumbnail` 使用硬化后的路径解析；
  - `/api/browser/image`、`/api/browser/thumb` 只接受图片扩展名；
  - `_cache_proxied_image` 写盘前同样校验。
- `app/routers/images.py`
  - `/api/images/{id}/download` 改用 `resolve_image_path`（尊重 `img_type` 与 junction）。
- `app/main.py`
  - CORS 从 `["*"]` 收窄到本机开发/生产来源；同源部署不需要通配。
- 测试：`tests/test_paths_security.py`（或并入现有契约测试）覆盖 `../`、绝对路径、盘符、非图片扩展名。

### B0-2 全库删除确认

- `DELETE /api/images` 增加 `confirm` 查询参数；未确认时只返回将影响的数量，不写库。
- 测试：未带 `confirm` 不改变数据；带 `confirm=true` 才软删。

### B0-3 导入提示词同步标签

- `app/routers/prompts.py::import_prompts` 在创建后调用 `sync_prompt_tags(r.id, tags)`，与单条创建保持一致。
- 测试：导入带标签的提示词后，`entity_tags` 可筛到、`usage_count` 正确。

### B0-4 分页排序

- `app/routers/images.py::list_history`
  - `oldest` 直接下推 SQL 排序；
  - `size_*`、`res_*` 先对筛选后的全集计算元数据并排序，再切片（避免“只排当前页”）。
- 测试：构造跨页数据，断言第 1 页和第 2 页的顺序连续正确。

### B0-5 ComfyUI 轮询快照化

- 测试：mock 客户端，断言一轮刷新只调用固定次数。

### B0-6 碎片自定义保存改走 prompts

## 3. 批次 1：出图归档（A+B+C）

### B1-0 交互与图片入口收敛（2026-11-01 追加）

- 提示词页顶部：新建/导入/导出保留，智能导入/补跑缺图/批量替换收进「更多」；
  碎片类型与标签收进「筛选」面板，永久工具栏从 5 行压到 3 行。
- 提示词详情的「出图历史」不再手拼 URL / `<a target=_blank>`：先取 id，再走
  `/api/images` 同一个序列化入口，缩略图、灯箱、收藏/删除/定位全部复用画廊组件。
- 新增 `useImageLocation` 与 `POST /api/images/reveal`（支持 id 或 filename+subfolder+type）：
  画廊卡片、灯箱、提示词出图历史、任务中心、组合结果中心、对比弹窗、图像选择器、
  图像编辑目标行都接入了「定位」；灯箱信息卡显示 `output/子目录/文件名`。
- 出图设置弹窗显示当前 output 根目录，并说明“根目录由 ComfyUI 决定”；
  新增「浏览…」目录选择器（`/api/system/output-folders`，可新建目录），
  不再要求手填子目录；磁盘选图页增加「打开目录」。
- 批量替换：
  - 弹窗改为固定高度 + 两栏自适应布局，候选/待替换列表吃满剩余高度，空态居中；
  - 替换内容输入框改为弹性高度（`flex:1`），候选列表按比例吃剩余空间；
  - 记住上次的碎片类型、替换内容、范围与“缺少时跳过/追加”策略（localStorage `pb.batchReplace`，300ms 防抖），
    再次打开自动恢复；「重置」可清空；
  - 缺少目标类型时可选择「追加」：后端 `POST /api/composition/batch_replace` 的 `missing=append`
    会在末尾追加 `【类型】\n内容`，预览标记「追加」，提交按钮变为“替换/追加并出图”；
  - 单条提示词详情新增「替换碎片」；批量替换移到勾选栏（选中后才出现）；
  - 替换碎片出的图不再挂原提示词：`prompt_id=None`，实际替换文本写入
    `prompt_params.prompt`（复用「临时提示词」展示），`source_prompt_id/name` 只作溯源；
    画廊卡片显示「替换」标记。
- 分页：
  - 移除分页行里重复的「全选本页」；
  - 勾选栏恢复为页面底部居中的椭圆悬浮条（`position: fixed; bottom: 24px; border-radius: 999px`），
    列表底部留出滚动空间，窄屏才退化为圆角矩形换行；
  - 分页行改为三栏：左总数、中分页 + 每页条数、右「定位」；滚动到当前选中的提示词。
- 目录选择器改用 Naive UI（`NModal`/`NCard`/`NInput`/`NButton`/`NEmpty`/`NScrollbar`），
  高度从 560 收到实际内容高度，空目录用 `NEmpty` 居中提示。
- **UI bypass/mute 语义**（2026-11-01 追加，解释 Krea2 “没反应”的直接原因）：
  - 旧 `ensure_api_format` 忽略节点 `mode`，把 UI 上 bypass 的第二程节点也提交给 `/prompt`；
    Krea2 两个“单程 8 步”工作流实际跑成了 8+4 双程，第二程（1.5x latent + 4 步 denoise 0.39）
    会重新组织画面、冲淡长提示词末尾的身材细节。
  - 现在 `mode=4` 按 ComfyUI bypass 语义做同类型输入直通，`mode=2` 直接断开；随后再解析下游连线。
  - 验证：两个 Krea2 工作流的 API 链路都变成 `KSampler(8 步) → VAEDecode`；ZIT 的 17+11 双程保持不变。
- **ComfyUI 实测：Krea2 vs ZIT（2026-11-01 追加）**：
  - 实验目录 `workflows/实验_20261101_Krea2对比/`，20 张固定 seed=123456789 的实拍图；
    条件、参数、逐张评分与结论见该目录 `README.md` 和 `contact_sheet.jpg`。
  - Krea2 原始长提示词在 8 步 CFG1 下身材基本不生效；ZIT 原始长版能画出衣服下的胸部轮廓，
    合并身材+服饰后更明显。
  - Krea2 短版/压缩版提示词能画出身材，压缩版还能保留制服细节；说明瓶颈是长提示词约束稀释，
    不是模型完全不会画。
  - **CFG2 在两条 Krea2 加速模型上不可用**：V8SE 全黑、V25 严重花屏；之前的“试 CFG 2–3”建议被实测否定。
    12 步 CFG1 不黑屏但也不解决身材；1MP 只提升速度。
- **自定义节点必填默认值**（2026-11-01 追加）：
  - `ResolutionPresetPicker` 当前版本新增必填 `base_name`，旧 ZIT 工作流 JSON 没有该字段，atelier 提交会 400。
  - `ensure_api_format` 现在按 ComfyUI `object_info` 的 default 补齐缺失必填项；
    未改原版 ZIT 可直接提交，且输出与手工补字段副本像素级一致。

## 6. 风险与注意事项

- **路径校验不能依赖 `Path.resolve()`**：Windows junction 可能抛 `WinError 448`，沿用 `_resolve_if_reparse` 的容错方式。
- **改 Save 前缀要同时注意** UI 格式工作流的 `widgets_values` 与 `widgets_values_named` 历史冲突；API 格式下以实际注入值为准。
- **不能破坏平铺默认值**：空子目录必须与旧行为逐字节一致，避免历史记录/测试基线漂移。
- **工作区已有未提交改动**：编辑 `prompts.py`、`composer.py`、`ComposerView.vue`、`useSettings.ts` 等文件时，先读当前内容，不做整文件覆盖。
- **不自动提交**：每批完成后报告 diff 与验证结果，等你确认再提交。
