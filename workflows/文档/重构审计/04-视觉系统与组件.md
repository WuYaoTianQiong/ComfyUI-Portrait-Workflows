# 04 · 视觉系统与组件（CSS 令牌 / 层叠 / 组件方言 / 响应式 / 视觉语言）

> 输入：`_审计简报.md`。范围：`static/` 下 10 个 CSS（4049 行 / ~100KB）、`index.html`（927 行）的 DOM、`static/vendor/`。只读代码，未改动任何源码。

## 0. 结论先行

1. **令牌只覆盖"颜色"，完全没覆盖"尺度"**：`:root` 15 个变量里 13 个是颜色，尺度只有 1 个 `--radius` + 1 个 `--shadow`。缺间距/字号/行高/z-index/动效/断点/控制高度 → 后果是 1147 个 `px`、219 个 `font-size`、14 个 z 值（1→200000）。
2. **层叠冲突的根不是 CSS 写法，是"JS 写内联样式 ↔ CSS 用 `!important` 反制"**。17 处真实 `!important` 里只有 7 处是纯 CSS 撞车，6 处对抗 `el.style.*`，1 处是死代码，3 处是冗余。`@layer` 能治好前 7 处、让后 10 处变成显式契约，但**打不过内联样式**。
3. **组件没有"套"，只有"每次就地写"**：20 种按钮、9 种下拉、12 种卡片、6 种空状态、10 种徽标、0 个 spinner、26 个原生 `confirm()/prompt()`。`.btn-xs` 被用 3 次却从未定义。
4. **响应式只有一个真断点 900px（重复写在 3 个文件）且已被 composer.css 打成 bug**：≤900px 表头换成两行后上下 padding 变 0；0 个 resize 监听；9 个控件 < 24px；全站 0 个 `aria-*` / `role=` / `tabindex`。
5. **审美收敛的正确顺序**：先补尺度令牌（只加不改）→ 再拆 JS 内联样式 → 再撤 `!important` → 最后才换图标。**反序做会满屏视觉回归且无法归因。**

**`@layer` 不能一次性解决：能治 11/17，剩 6 处是内联样式战场**（规范里内联样式永远高于任何 layer，只有 `!important` 压得住）。可行方案：① 新建 `layers.css`（6 行）在 `index.html:9` 之前加载 `@layer vendor, tokens, reset, base, components, screens, overrides;` ② 每个现有文件**只加 2 行**包 `@layer components { … }`，不重排不缩进（10 文件 / 20 行）③ `@import url("/vendor/viewer.min.css") layer(vendor);` 移进 `layers.css` ④ 之后才删重复块与 `!important`，且**必须分两次提交**（重要声明在 layer 中顺序反转，混着改会静默翻转赢家）。
**兼容性**：`@layer` Chrome/Edge 99+、Safari 15.4+、Firefox 97+（2022）——本项目已在用 `color-mix()`（8 处，Chrome 111+/Safari 16.2+，2023），layer 门槛**低于现有代码**，零新增风险。**一个容易忽略的机制**：unlayered 样式（`<link>` 引的 vendor、`index.html:684-713` 的内联 `<style>`）优先级高于所有 layer。当前我们对 `.viewer-*` 的覆盖规则是 **0 处**（实测），所以今天不会踩；但第 ③ 步仍必须做——否则日后任何人想微调灯箱，都得先想到"我的规则在 layer 里，压不过 vendor"。

### 1.5 响应式与可用性

- **断点** 6 个 `@media`：900px×3（`components.css:422`、`composer.css:530`、`composer2.css:774`）+ 180px（`composer2.css:283`，**用视口断点响应"列宽"，应是 `@container`**）+ 1100/1101 一对（`faceswap.css:256,520`）。
- **JS 侧 0 个 `resize` 监听、0 个 `matchMedia`**；侧栏宽度以 px 内联持久化并恢复（`ui.js:65,123`），窄窗不收缩。
- **大屏**：无 `max-width` 容器，`.detail{padding:24px}` 正文行长在 2560 屏上超 150 字符；画廊列宽靠 JS 算 `--gallery-thumb-size`（`gallery.css:96`）。
- **触摸目标**：`.active-filter-chip button`≈12px、`.label-icon-btn`≈14px（`height:1.2em`）、`.fs-item-zoom`≈16px、`.fs-dir-chip`≈19px、`.page-btn`/`.wf-item-hide`≈20px、`.fs-col-toggle` 20×20、`.wfa-btn` 22×22、`.icon-btn`≈23px → **9 个 < 24px**（WCAG 2.2 AA 下限），全部 < 44px。
- **焦点**：`base.css:20` `*:focus{outline:none}` + `:21` `*:focus-visible{box-shadow:0 0 0 2px rgba(99,102,241,.35); border-radius:4px}`。两个问题：环色是 `--primary` 的**硬编码副本**（换主色环不变）；该规则会**给被聚焦元素补一个 4px 圆角**，圆形/胶囊控件聚焦时形状跳变。
- **键盘**：`aria-*`=0、`role=`=0、`tabindex`=0。`Esc` 只关 4 个弹窗（`ui.js:92-97` 硬编码 `closeModal/closeVarModal/closeWfModal/closeCompareModal`），其余 7 个 overlay 无 Esc；无焦点陷阱、无返回焦点；`Enter` 仅搜索框/路径栏 3 处。`Ctrl+Enter` 跑图、`Ctrl+S` 保存已有（`ui.js:98-107`）。
- **对比度**：`--muted#8e8e99` on `--panel#141418` ≈ 5.6:1（合格）；但 3 处再乘 opacity（`.workbench-empty-hint` .6、`.fs-section-hint` .65、`.workbench-editable-hint` .7）→ ≈ 2.9~3.4:1，**不合格**。

### 1.6 视觉语言：emoji 作为图标系统

现状：纯暗色（`#0c0c0f`）+ 靛蓝主色 + emoji 图标 + 6 色系约 20 种色值 + 13px 紧凑密度 + 全出血面板。**"个人工具"的气质是真实资产**：像笔记工具而不像 SaaS，密度高、无多余留白。实测 **348 处字形 / 74 个码点**（`index.html` 62 处 36 种，`prompt.js` 63 处 37 种）。问题不是"用了 emoji"，是**没有边界**：

1. **同义重复 5 组**：关闭 `✕`10/`✗`1/`×`；箭头 `▼`5/`▾`8/`▸`3/`▶`4/`◀`1；星 `★`8/`☆`8/`⭐`2；勾 `✓`7/`✅`4；文件夹 `📁`6/`📂`2/`📦`8。
2. **层级混用**：chrome 层（Tab、表头按钮、关闭）与文案层（`"⏳ 排队中"`、`"✅ 已完成"`）共用一套字形，后者其实是**句子的成分**，不该被"图标化"。
3. **技术缺陷**：彩色 emoji 无法 `color` 调色（hover 只能换字形）、宽度/基线随平台字体（Windows/Noto/Apple 三套）漂移导致同一行按钮文字跳动、无法用 `currentColor` 跟随主题。

## 2. 根因分析

- **R1 文件按"什么时候加的"命名，不按"管哪一层"命名**。`modal.css` 装的是标签/分类管理，`stats.css` 同时装统计卡+碎片按钮+`.modal-footer`，`frag.css` 只有 11 行且只为 `.frag-tag` 存在。没有构建就没有强制入口，于是每个 Phase 自带一份 CSS 尾巴 → 679 个选择器里 28 个被重复定义、9 组跨文件撞车，是命名的必然结果，不是疏忽。
- **R2 令牌表没给"尺度"留位置**。15 个变量 13 个颜色，写间距/字号时"没有正确的变量可用"，只能写字面量。这不是懒，**是令牌设计只考虑了配色、没考虑排版**。同时 `--radius` 明明存在却只有 13% 采纳率——"有令牌"≠"会用令牌"，还需要约定。
- **R3 CSS 与 JS 通过内联样式互相喊话**。161 处 `style="…"`（HTML 59 + JS 102）+ JS 直接写 `el.style.color/borderColor/background/display`。CSS 想盖住内联样式只有两条路：`!important` 或 `:has([style*=…])`。`composer2.css:833` 靠内联样式字符串做选择器，是这条路的终点——**它是这个架构的自白**。
- **R4 反馈只有"动作"，没有"组件"**。每次都是"这里需要一个提示"就地写一行，从没人问"有没有 `.empty-state`" → 26 个原生 `confirm()`、6 套空状态、0 个 spinner、10 套徽标。**越常用的界面越简陋**，这是"缺组件"而非"缺设计"。
- **R5 "个人工具"的审美没被写成规则**。emoji 当图标是效率选择也是审美选择；问题是没人规定"chrome 层用图标、文案层用文字"，于是 74 个码点自由生长。同理强调色从 4 个语义色溢出到 6 色系 20 种色值（紫 `#a855f7` 给"处理"、蓝 `#3b82f6` 给"提示词"、青 `#5b8fb9` 当标签默认），因为**没有"新颜色需要理由"的门槛**。

格式：**现状 → 目标｜最小改法｜影响文件｜风险｜工作量**（S ≤ 半天、M ≤ 2 天、L > 2 天，单人）。

## 4. 明确不建议做的事

- **不要一次性替换 348 处 emoji**。全项目最贵、最容易毁掉"个人工具气质"的改动：字形散落在 14 个 JS 的模板字符串里，很多是句子成分（`"⏳ 排队中"`、`"✅ 已完成"`），换 SVG 会破坏排版与语义。**只换 chrome 层 15 个（U13）**。
- **不要引入任何 CSS 框架/原子类/预处理器**。需要构建，且会把 679 个选择器变成一次性全量重写；用户已明确排除。
- **不要同时改 `@layer` 层序和删 `!important`**。重要声明在 layer 中顺序反转，混着改会静默翻转赢家，且没有视觉回归手段可归因。
- **不要把标签/分类颜色"收敛"**。那是用户数据（`index.html:492` 的用户取色、`gallery.css:917` 的 `--c` 内联注入），不是设计令牌。
- **不要为了统一而削平密度**。13px/6px 的紧凑感是资产，不是缺陷。令牌化目标是"同一个值只有一个来源"，不是"变大变松"。
- **不要碰 `vendor/viewer.min.css`**（9 行压缩 / 7.6KB）。它与我们的 CSS **零交集**（实测 0 处 `.viewer-*` 覆盖）；`gallery.css:1-23` 那 23 行 `.pswp-*` 是已卸载的 PhotoSwipe 遗留（`window.pswpLightbox` 恒为 `null`，`imageViewer.js:1059`），直接删掉即可（U4），不需要去"覆盖"它。
- **不要在 U1 落地前搬 `index.html:684-713` 的 30 行内联 `<style>`**。搬走是对的，但它的优先级取决于是否 unlayered；顺序错了灯箱会坏。

## 5. 与其他分报告的交叉点（可能冲突）

1. **与"双渲染模型 / HTMX"报告**：U12/U13 要同时改 Jinja2 片段（`/api/prompts/html`、`/api/history/html` 等 6 个端点）与 JS 模板。若那边收敛到单一渲染路径 → **等它落地再做 U12/U13**；若保留双渲染 → 每个组件外壳要改两遍。建议：先收敛渲染路径，再统一组件。
2. **与"前端 JS 模块化 / window 全局"报告**：剩余 6 处 `!important` 的解除依赖 JS 停写内联样式（`composer-core.js:282,301,596`、`composer-workbench.js:38`、`faceswap.js:139,140,210`）——**这是同一批代码行**。若那边正在拆 `composer-core.js`，必须合并为一次改动，否则两分支必然冲突。
3. **与"文件组织 / index.html 拆分"报告**：`index.html:684-713` 的 30 行 `<style>` 应独立成 `dynamic-modal.css`，属它的领域；若那边正在把 927 行拆成片段，应一起做。
4. **与"性能 / 首屏"报告**：U1 把 `viewer.min.css` 从 `<link>` 改成 `@import … layer(vendor)` 会串行化 CSS 加载（本地无感，但多一次往返）。若性能报告在压关键路径请求数，这里有**真实冲突需裁决**；替代方案是保留 `<link>`，把 12 行 vendor 覆盖放进 unlayered 的 `overrides.css`（未分层优先级最高）。**这条必须由主报告裁决。**
5. **与"交互 IA / 4 个跑图入口 / 2 套批量面板合并"报告**：合并会删 DOM 与 class。**令牌表 U5 可以先落地**（纯增量），但 U7/U8/U11/U12 应等 DOM 定型，否则改的是即将被删的节点。
6. **与"可访问性"专章（若独立成篇）**：Q4 的焦点/键盘/对比度我已覆盖，U14/U15 是视觉层最小必要。建议分工：**我出视觉令牌与焦点环，它出语义（`role`/`aria-live`/焦点陷阱/`aria-label`）**，避免两边都改 `ui.js:90-109`。
7. **对简报的两处修正**：`!important` 是 **19 处字符串 / 17 处真实声明**（`composer2.css:603`、`modal.css:236` 是注释字样）；跨文件同名选择器是 **9 组**（简报列 5 组，另有 `.modal-footer`、`.detail-actions`、`.gallery-item-process`、`.gallery-item-prompt-btn`）。
