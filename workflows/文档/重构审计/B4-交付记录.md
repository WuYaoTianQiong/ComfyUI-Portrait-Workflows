## 一、先落地的三件数据语义（commit `b15e4d7`）

### 1. 删提示词不再删图

`delete_prompt` 之前会 `GenHistory.delete()`：删一条提示词，它名下所有出图记录一起消失，
而磁盘文件还在 —— 下次同步又把图扫回来，表现为"删不干净 + 记录反复重建"。
现在改为 `prompt_id = NULL`（只解除关联），返回体新增 `gen_history_detached` 计数。

### 2. 画廊读取不再写库

`_enrich_item` 里原来会 `Gh.update(prompt_params/prompt_id)` 并继承分类 —— 打开一次画廊就写一次库。
现在只从任务 items 里取出来给本次展示用；真正的补写只发生在入库路径。

### 3. 软删除墓碑已清理

生产库清理前：`gen_history` 1206 行，**存活 0、墓碑 1206**（17:36 的 cleanup_missing 把最后 47 张也标删了）。
执行 `tools/cleanup_tombstones.py --yes`：

| 项目 | 结果 |
|---|---|
| 删除墓碑 | 1206 条 |
| 删除关联 | 图片标签 1121 条、图片分类 171 条 |
| 保留 | `prompts` 308、`templates` 358、`template_fragments` 2308、`tags` 136、`categories` 4、`gen_jobs` 109 |
| 数据库体积 | 3,211,264 B → 2,084,864 B（VACUUM 生效） |
| 完整性 | `PRAGMA integrity_check = ok` |
| 备份 | `文档/提示词收藏.db.bak_tombstone_20261018_180142`（清理前，含全部 1206 行） |

脚本可重复使用，默认预演，`--yes` 才执行，`--keep-recent N` 可保留最近 N 天。

## 三、B4 第 2 步：删除休眠的 HTMX 分支（commit `773872b`）

生产态默认就是 JS 渲染，HTMX 只在 `?htmx=1` / `localStorage.htmxMode=1` 时启用，
且该分支已落后主路径三个功能。整体删除：

| 位置 | 改动 |
|---|---|
| `index.html` | 移除 htmx 脚本、三处 `hx-*` 与 `hx-vals` |
| `app.js` | 移除 `?htmx=1` 检测、`hx-*` 剥离、`htmx:afterSwap`、`htmx:beforeRequest` |
| `prompt.js` / `history.js` / `gallery.js` / `fragments.js` | 移除 5 处 `htmxActive` 分支 |
| 后端 | 删除 `/prompts/html`、`/history/html`、`/fragments/html` 三个端点与 4 个 Jinja 模板 |
| 依赖 | 删除 `vendor/htmx.min.js`（51KB） |

契约测试改为断言旧端点不再返回页面；冒烟改为"已下线"检查。

## 四、B4 第 3 步：换脸画廊接入分类/标签筛选（commit `71f672b`）

换脸工作台的画廊模式原来只能按关键词搜索，后端 `/api/history` 早就支持

两栏共用同一套筛选，切筛选自动回到第 1 页。

## 五、B5 第一批：令牌与层级（commit `3247398`）
