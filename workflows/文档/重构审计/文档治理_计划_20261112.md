## 一、问题诊断（带证据）

### 1.1 为什么「工作流清单.json」与「资产清单.md」不能合并

| | `工作流清单.json`（Atelier 机器视图） | `资产清单.md` 1.1/1.2（人读视图） |
|---|---|---|
| 目的 | 稳定身份：改名/换目录后历史任务仍可追溯 | 讲清「怎么用、多快、有什么坑」 |
| 关键字段 | `wf-<sha1(路径)[:12]>`、`sha256`、`slots`、`quality_mode`、`status` | 用途、实测耗时、踩坑、选型理由 |
| 生产者 | 程序（`脚本/atelier/tools/gen_workflow_manifest.py`） | 人 |
| 消费者 | 程序（`app/services/job_state.py:434` 每次提交调 `identify()`；`audit_workflows.py` 等） | 人 |
| 数据可得性 | 扫磁盘即可重建 | 必须实测才有 |

`workflow_manifest.py` 的设计注释写得很明确：*「文件名只是显示标签，不能当身份」*。这个能力只能由带 sha256 的索引承担；md 承担不了，json 也装不下中文判断。**所以「合并」是错误方向，正确方向是「单一事实源 + 派生 + 自动校验」。**

### 1.2 真正的四个毛病

| # | 问题 | 证据 |
|---|---|---|
| 1 | 两套记录靠人手同步 | 2026-11-12 归档 ZIT 时，需人工做「移文件 + 重跑 manifest + 手改 md」三步，任一漏掉即漂移 |
| 2 | 资产清单章节编号断裂 | 原为「一、三、五、六、九、十二」，二/四/七/八/十/十一 全缺（历史上删章未重排） |
| 3 | 文档索引已腐化 | `文档/README.md` 索引漏收 4 份新文档（FLUX3 / MOSS / H3 / 横向对比） |
| 4 | 同一层内部碎片化 | Atelier 相关 7 份、参考图库合成台 5 份并存，都在讲同一模块的不同批次 |

### 1.3 哪些并行是「合理分层」（不要动）

| 主题 | 份数 | 为什么合理 |
|---|:--:|---|
| 工作流状态 | 2（json + md） | 机器身份 / 人读知识，职责不同 |
| 实测记录 | 5（Krea2/FLUX3/MOSS/H3/横向对比） | 时序记录「只增不改」，对应不同模型与日期 |
| ZIT 认知 | 3（主册 902 行 + 踩坑日志 1787 行 + 作者动态 275 行） | 长期结论 / 时序证据 / 上游动态，三层 |
