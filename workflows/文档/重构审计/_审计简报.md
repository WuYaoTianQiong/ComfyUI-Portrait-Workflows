## 3. 已核实的关键症状（供各报告引用，不必重新论证）

1. **双渲染模型**：`index.html` 中提示词列表与画廊列表走 `hx-get="/api/prompts/html"`、`/api/history/html"`（Jinja2 片段）；其余弹窗、组合、换脸走 JS 拼 HTML。`static/app.js:67-79` 存在 `?htmx=1` 模式开关，非 HTMX 模式会运行时剥离 `hx-*` 属性；注释明确记录了 HTMX swap 与 JS 渲染的竞态（"过滤图闪现后被全部图片覆盖"）。
2. **4 个跑图入口**：头部 `#runBtn`、组合 `#composerRunBtn` / `#composerBatchRunBtn`、换脸 `#fsSubmitBtn`；头部画质/横竖屏/跑图按钮按 Tab 隐藏（`static/ui.js:168`）。
3. **2 套批量面板 + 3 个进度面**：`#batchPanel`（提示词 Tab）、`#fsPanel`（换脸 Tab）为近似重复的 DOM/CSS；另有 `#outputArea` 单任务进度。
4. **任务轮询有副作用**：`GET /api/jobs/{id}` 每次调用都写库（`routers/jobs.py:208`），前端 1s 轮询（`static/job.js:17`），后端另有 5s 监控循环（`main.py:25-55`）调用同一函数；每次快照都请求 ComfyUI `/queue` 与 `/history?max_items=500`（`routers/jobs.py:80-92`）。
5. **同步阻塞**：全部端点是同步 `def` + 阻塞 `httpx.Client`；`job_monitor_loop` 是 `async def` 但内部执行同步 DB 与 HTTP，会阻塞事件循环（`main.py:30-53`）。
6. **前端一次只能轮询一个任务**：`window.jobPollTimer` 单例，`trackJob` 会清掉上一个定时器（`static/job.js:16`）。
7. **分类/标签体系在提示词与图片上各存一份**：`PromptCategory`/`PromptTag` 与 `ImageCategory`/`ImageTag` 四张关联表（`models.py:125-170`），靠 `inherit_prompt_taxonomy` 快照拷贝（`models.py:173`）。
8. **API 返回结构不统一**：集合键混用 `items` / `prompts` / `jobs` / `categories`；成功响应有时 `{success:true}`、有时裸对象、有时带 `total/page`。
9. **状态持久化分裂**：`UiState`（`static/ui.js`，localStorage 键 `promptBrowserUiState_v3`）+ 十余处裸 `localStorage` 键（`gallery.js`、`workflow.js`、`composer-core.js`）；`composerTemplates_v4` 是已迁移到 DB 的遗留键（`composer-core.js:75`）。
10. **错误处理**：后端 60 处`except Exception`/裸 `except`，45 处 `print`（日志中文在 `_pb_out.log` 里是乱码，说明 Windows 控制台编码未处理）；无结构化日志、无请求 ID。
11. **SQLite 配置**：`journal_mode=delete`（`models.py:11`），配合线程池同步端点各自建连接，存在写锁竞争风险。
12. **测试**：仅 `verify_smoke.py`（起临时端口打真实 HTTP 的冒烟脚本），无单元测试、无前端测试、无 CI。

## 4. 分报告统一格式

每份报告 ≤ 200 行 Markdown，中文，结构固定：

```
# 分报告标题
## 0. 结论先行（5 行以内）
## 1. 现状盘点（带文件:行号证据）
## 2. 根因分析（为什么会长成这样，不要只列现象）
## 3. 统一机会清单（编号 U1..Un）
    每条：现状 → 目标形态 → 最小可行改法 → 影响文件 → 风险 → 工作量(S/M/L)
## 4. 明确不建议做的事（防过度设计）
## 5. 与其他分报告的交叉点（可能冲突的地方）
```

## 5. 审计纪律

- **只读**：不得修改 `prompt_browser_v4` 下任何代码；只在 `workflows/文档/重构审计/` 写自己的报告文件。
- 每个结论必须能找到 `文件:行号` 依据；推断要标注"推断"。
- 不要提议"全部重写"。所有建议必须能拆成可独立上线的小步。
- 不要为了架构洁癖牺牲用户已习惯的操作路径；判断标准是"用户少点几次、少想一次"。
