# 02 · 前端架构与状态

> 审计对象：`static/*.js`（20 个业务 JS + 2 个 vendor 库，均只读）、`static/index.html`、`static/templates/*.jinja2`。
> 实测口径：`innerHTML` 107 处、内联处理器 323 处（其中 `onclick=` 284）、`addEventListener` 45、`getElementById` 422、`createElement` 65、`window.X =` 779 次 / 唯一名字 476 个。

## 0. 结论先行

1. 生产态其实已是"JS 渲染单轨"：HTMX 只在 `?htmx=1` 或 `localStorage.htmxMode=1` 时启用（`app.js:69`），而该分支已与主路径分叉（分页丢分类/标签、分面参数后端不认、新建按钮函数名写错）。
2. 最大根因不是缺框架，而是**没有状态所有权**：查询/选择状态有 4 套副本，跨 12 个文件写同一批语义。
3. 上帝对象：`prompt.js`（149 全局 / 78KB）、`history.js`+`gallery.js`（合起来是同一部 GalleryController，共 144 全局）、`app.js`（引导器，出边 14 个模块）。
4. 只切一刀：**先建 `store.js` 收拢"列表查询 + 选择"**；渲染器重复只是外显症状。
5. 收敛方向：保留 JS 渲染、删 HTMX（排在状态统一之后、HTML 端点最后删，与 01 报告的"最后删"一致）。

## 1. 现状盘点

### 1.1 运行时结构与实际依赖图

- `index.html` 共 22 个 `<script>`：2 个 vendor（`index.html:20-21`）+ 20 个业务脚本按手写顺序加载（`index.html:906-925`），无 `type=module`、无 import/export。
- 实测（简报记 775，差异为 `+=` 与重复赋值）：`window.X =` 779 次、唯一名字 476 个 → **42 个名字被 2 个以上文件重复定义**（`_galleryPage` ×2、`_promptPage` ×5、`loadTags` ×2、`selectedIds` ×2…），谁最后加载谁生效；`tag.js:7` 的 `function loadTags` 覆盖了 `prompt.js:1354` 的 `window.loadTags`（`index.html` 910 行先加载、918 行后加载），`#tagFilter` 从此永不填充，且错误被 `try{}catch(_){}` 吞掉。
- 实测扇入（被几个文件引用）：`showToast` 16、`API` 15、`escHtml` 13、`UiState` 11（共 90 处引用）、`withLock` 10、`trackJob` 7、`loadHistory` 6 文件 14 个调用点、`loadPrompts` 25 个调用点、`_gallerySelectedIds` 4 文件。

```
vendor/htmx(51KB) ── 仅 ?htmx=1 路径 ──> 3 个 /html 端点 + 4 个 Jinja 模板
utils(api/esc/showToast/withLock) ←── 20/20 文件
ui(UiState 30+ 键) ←── 12 文件 / 90 处
workflow ← prompt, generator, composer-core, faceswap, imageViewer
prompt ⇄ generator ⇄ job ⇄ history ⇄ gallery ⇄ imageViewer   ← 6 个文件成环，无分层
app ──> 14 个模块（bootstrap + 全局声明 + 3 个定时器 + 2 个 htmx shim）
composer-core ⇄ composer-{workbench,random,templates,fragments}
category/tag ──> prompt（loadPrompts）
```

- **`prompt.js`**：149 个全局，一个文件同时是列表/详情/编辑器/导入导出/试跑/模板（`prompt.js:8,176,444,741,983,1354,1566,1713`）。
- **`history.js` + `gallery.js`**：`loadHistory`/`_loadHistoryPage` 在 history，`renderGallery`/选择/侧栏在 gallery，却共用 `_gallery*` 20 余个全局；`loadHistory` 在 6 个文件 14 处被调用，任何"刷新"都要穿过这两文件。
- **`app.js`**：全局声明（`app.js:9-28`）+ 从存储恢复（`:32-59`）+ htmx 补丁（`:67-132`）+ 引导（`:134-190`）；它知道所有模块，但没有任何模块知道它。
- **`UiState`** 是另一个意义的上帝对象：30+ 个无 schema 的键，12 个文件写，`set()` 每次都整包 `JSON.stringify` 落 localStorage（`ui.js:22-35`）。
- **先切哪一刀**：`store.js`。因为 12 文件×90 处 UiState、6 文件×14 处 loadHistory、25 处 loadPrompts、4 文件共享 `_gallerySelectedIds` 都指向同一件事；渲染器重复可以晚一步（03 报告也主张"先统一状态而不是渲染器"）。若先切渲染器，状态仍会在 Jinja/JS 两侧各长一份。

### 1.2 渲染模型分裂：每个补丁在治什么

- `?htmx=1` 开关（`app.js:67-79`）：同一页面并行两套渲染器。关掉时**在 DOMContentLoaded 前剥离全部 `hx-*`**，目的是抢在 htmx 的 `load` 触发器之前，避免它和 `loadHistory()` 的 JSON 请求同时打同一容器——注释明确记录了"过滤图闪现后被全部图片覆盖"（`app.js:61-66`）。
- `hx-*` 剥离（`app.js:75-77`）：只处理 index.html 里的静态节点；Jinja 模板里的 `hx-get` 是后注入的，靠模式开关整体不启用，**不是靠剥离**。
- `galleryRefresh`/`promptListRefresh`/`fragmentListRefresh`（`history.js:29`、`prompt.js:36`、`fragments.js:47`）：把"请重载列表"的统一呼喊翻译成两种实现——JS 模式直接调 loader，HTMX 模式用 `hx-trigger="... from:body"`（`index.html:156,293,552`）。它们解决的是**双路径调用点统一**，不是竞态。
- `htmx:afterSwap`（`app.js:88-105`）：swap 后重新给选中项加 `.checked`、重算按钮——因为选中集合在 JS 内存里，服务端 HTML 不知道它。这是"状态不在 DOM、却用 DOM 当状态"的补丁。
- `htmx:beforeRequest`（`app.js:116-132`）：从请求 URL 反推 `_galleryPage/_Sort/_Filter/_Search`，因为模板分页按钮自己拼 URL，绕过了 JS setter。这是第 3 套参数装配路径（另两套：`history.js:65-78` 与 `index.html:296-307` 的 `hx-vals`）。
- 已分叉的证据：`/api/history/html` 只收 7 个参数（`history.py:750-760`），JSON 版多 4 个分面参数（`history.py:383-394`），所以 HTMX 下点击"来源/时间/模型/方向"chip 只改 UI 不发筛选；画廊分页链接只带 `page/page_size/sort/favorite/search`（`templates/history/list.jinja2:69-87`），切页即丢分类/标签；`templates/fragments/list.jinja2:16` 调的 `window.openCreateFragmentModal` 全仓不存在；提示词模板缺置顶按钮（对比 `templates/prompts/list.jinja2:44-51` vs `prompt.js:218-225`）。
- **定案：保留 JS 渲染，删除 HTMX。** 理由：它已是默认（`app.js:69`）；只有它具备全功能；HTMX 分支每加一个筛选项要改 4 处（JSON 端点、HTML 端点、Jinja、hx-vals），而收益（少拼 HTML）被"其他 90% 界面仍手写 HTML"抵消。注意 `vendor` 两库（htmx 51KB + Viewer 45KB）在默认模式下是纯下载成本，Viewer 只在 Ctrl+点击这一隐藏路径可用（`imageViewer.js:1030-1041`）。

### 1.3 四套状态源与互相污染（3 个可复现场景）

| 状态源 | 载体 | 规模 | 谁写 |
|---|---|---|---|
| 全局散变量 | `window._gallery*` / `_prompt*` / `selectedId(s)` | 20+ 个 | app/history/gallery/prompt/category/tag |
| UiState | localStorage `promptBrowserUiState_v3` | 30+ 键 / 90 引用 | 12 个文件，任意时机 |
| 裸存储键 | `gallery_sidebar_width/collapsed`、`gallery_group_*`、`pb_workflow_*`、sessionStorage `pb_lightbox_state`、`pb_draft_*`（`gallery.js:650-710`、`workflow.js:4-5`、`imageViewer.js:998`、`prompt.js:930-951`） | 8+ 键 | 各自为政，无版本/迁移 |
| 模块闭包 | `let _selectedTags`（`tag.js:4`）、`_locks`（`utils.js:7`）、`_fsSel` Map、`_trialRuns`、`_importItems` | 不可枚举 | 仅本文件可见 |

- **场景 A（已确认）：标签多选是空操作。** `tag.js:4` 用顶层 `let` 声明 `_selectedTags`，它进不了 `window`；而所有消费者读的是 `window._selectedTags`（`prompt.js:22,58,348`、`composer-core.js:196`）→ 永远 `undefined`。用户勾选标签，列表重载但请求里没有 `tag_ids`，触发器仍显示标签名/N 个标签（`tag.js:98-112`）。
- **场景 B（代码路径确认，界面效果为推断）：HTMX 下切页丢筛选。** 分类/标签筛选后点第 2 页，模板 URL 不含 `category_id/tag_ids`（`templates/history/list.jinja2:69-87`），`beforeRequest` 只回写页码，于是"侧栏仍高亮分类、网格已显示全部"。
- **场景 C（已确认，最危险）：隐藏选中项参与批量删除。** 分类/标签/分面切换都不清空 `_gallerySelectedIds`（`gallery.js:491-532`；只有搜索/排序/收藏筛选会清，`history.js:448-456`）。先选 3 张，再切分类，选中集合仍含不可见图；"删除选中"直接按集合发 DELETE（`history.js:337-355`）。叠加"全选全部"只传 favorite/sort/search/orientation、不传 category/tag（`gallery.js:205-209`，后端支持，`history.py:568-569`），且该路由当前因装饰器挂错而 422（`history.py:498-499`，06 报告已核实）——修好路由前它是坏的，修好后若不同步参数就是**误删放大器**。
- **附带**：换脸任务被两个 tracker 同时跟踪（`job.js:33-49` 的 `items>1` 条件 + `faceswap.js:114,697-701`），两个 1s 轮询器打同一 job，各自在完成后刷一次 `loadHistory`；`gallery.js:388-389` 还有未声明的 `promptText/negText` 隐式全局。

### 1.5 DOM/XSS 面与内联事件成本

- 107 处 `innerHTML` 拼装、65 处 `createElement` 混用。转义工具存在且多数高危点已用（`escHtml/escAttr`，`utils.js:108-125`），但"转义函数放进 JS 字符串上下文"系统性错误：
  1. `gallery.js:388-398`：提示词文本 `JSON.stringify` 后直接拼进 `onclick="navigator.clipboard.writeText(" + text + ")"`，引号立即截断属性——正常带引号的提示词让复制按钮失效；构造 `" onmouseover="...` 可注入处理器（推断：需要在图片参数弹窗里点开才触发）。
  2. `templates/prompts/list.jinja2:8`：`'{{ p.name|e }}'`——`|e` 产出 `&#39;`，HTML 解析器会先把它解码成 `'` 再交给 JS，等于没转义；名称带单引号即断（含注入可能，推断）。
  3. `tag.js:34`：同一错误（`escAttr` 后塞进 `'...'`），标签名带 `'` 即断。
  4. `app.js:206`：统计页标签名 `${t.name}` 完全未转义 → 自建标签名即可存储型 XSS。
  5. `gallery.js:549,554,559,567`：`JSON.stringify(k)` 塞进单引号属性，模型/日期值含 `'` 即断。
  6. `prompt.js:1747`：文件名只替换 `'`，未处理 `"`，可截断 `onclick` 属性（推断）。
- 结论：XSS 面不在"展示提示词正文"（那里逐处 `escHtml` 了），而在**用户数据进入内联处理器/属性**这条窄缝。单机自用降低了外部攻击面，但导入的提示词包（`/api/prompts/import`）、ComfyUI 元数据、分享的 JSON 都可携带 payload，执行后即可调本地 API 删图。
- 内联处理器 323 处（index.html 166、JS 模板串 157），`addEventListener` 仅 45 处：迁移成本主要在**动态渲染器**（每处要改成 `data-action`+`data-id` 并接到统一委托表），静态 HTML 的 166 处可用一次 document 级委托批量吃掉。粗估：静态 1–2 人日、动态 3–5 人日、回归 2–3 人日。替代方案：`data-action` + 单一 `click` 委托 + 渲染器只产出 DOM/转义文本；不引入模板引擎。

## 2. 根因分析

1. **Phase 式增量只加不换**：Phase 2 加 HTMX、Phase 5 加 Viewer.js/换脸面板，旧路径一律保留（`app.js:67` 开关、`imageViewer.js:1030` 兼容层、`pswpLightbox` 只剩 destroy）。每条新路都复制一套状态与渲染，默认值替旧路"关掉"而非删除。
2. **window 是唯一集成层**：没有模块边界，"导出"就是 `window.x =`。于是同名互相覆盖（42 组）、`let` 与 `window.` 两套可见性（场景 A）、函数名冲突（loadTags）都成了默认风险。
3. **状态无主**：谁需要谁 `UiState.set`，没有 schema、没有单一写入者、没有订阅；持久化键随手新建，旧键只在注释里迁移（`composer-core.js:75`）。
4. **单文件壳当 schema**：`index.html` 927 行承载 5 Tab/12 弹窗，ID 即接口（422 次 `getElementById`），所以"加功能=加一段 HTML+一段 onclick"，复用只能靠复制。
5. **无测试 + 无类型**：重复比抽象安全，分叉无人发现（HTMX 三个分支 bug 都在默认关闭的路径里活了下来）。

## 3. 统一机会清单

### U1 单一状态仓库（先做这一刀）
- 现状：4 套状态源；12 文件 90 处 UiState；`_gallery*`/`_prompt*` 20+ 全局；查询参数在 3 处装配。
- 目标：`store.js` 持有 `{prompt:{page,size,sort,order,search,categoryId,tagIds}, gallery:{...}}` + `selection`，只暴露 `get/set/subscribe`；UiState 降级为"序列化后端"（同一份 schema，一个 key），页面控件只读 store。
- 最小改法：先建 store 并让 `loadHistory/_loadHistoryPage/loadPrompts/renderGallery/renderList` 从 store 取值；旧全局改成 `Object.defineProperty` 代理到 store（读旧名仍可用），逐个删调用点；顺带抽 `buildGalleryQuery()/buildPromptQuery()` 供 JSON loader 唯一使用。
- 影响：`app.js/history.js/gallery.js/prompt.js/category.js/tag.js/ui.js`。｜风险：代理期属性描述符写法出错会静默失效，需逐屏手测。｜**M**

### U2 渲染器收敛（保留 JS，删 HTMX）
- 现状：双渲染 + 3 个 `/html` + 4 个 Jinja + 3 套参数装配；已分叉（1.2）。
- 目标：单一 JS 渲染器；Jinja 只留 `base.jinja2`（如仍需要）。
- 中间态（可独立上线）：M0 冻结——新筛选项一律不进 `/html`（默认路径已不用）；M1 修 1.2 列出的分叉 bug 或明确"实验模式"告示；M2 抽 U3 组件后，JS 渲染器输出与模板逐项对齐（置顶/分面/跨页全选）；M3 删 `hx-*`/开关/`htmxActive` 10 个分支 + vendor/htmx；M4 最后删 3 个 HTML 端点与 4 个模板（尊重 01 的"最后删"）。
- 影响：`app.js/history.js/prompt.js/fragments.js/index.html/templates/*`。｜风险：M3 一次删太多，按"M3a 开关、M3b 分支、M3c 库"三次提交。｜**M**

### U3 列表/网格组件 + 选择控制器
- 现状：4 份网格、5 份选择模型（1.4）。
- 目标：`components/list.js` 提供 `renderGrid(items,{itemTpl,onOpen})`、`createSelection({mode:'set'|'range'|'pair'})`；画廊、换脸、提示词历史、试跑日志共用；选中态只从 store 读，切换筛选时按策略显式清空。
- 最小改法（无构建）：`index.html` 放 `<template id="tpl-gallery-item">`，组件用 `cloneNode` + `textContent` 填充，禁止拼 HTML 字符串；选择控制器暴露 `toggle/clear/rangeTo/ids()`。
- 影响：`gallery.js/faceswap.js/history.js/prompt.js/index.html`。｜风险：换脸有"文件夹模式"与双角色，先只共用"画廊模式"分支。｜**L**

### U4 事件委托 + 安全渲染规范
- 现状：323 内联处理器、6 类转义上下文错误（1.5）。
- 目标：`data-action="gallery.fav" data-id="..."` + 一个 document 级 `click/change/input` 委托表；规则：用户数据只进 `textContent`/`dataset`，绝不进 `on*` 属性或 JS 字符串。
- 最小改法：先修 6 个高危点（gallery prompt 参数、tag.js:34、prompts/list.jinja2:8、app.js:206、facet chip、prompt.js:1747）；再给新代码强制 `data-action`；静态 166 处按 Tab 分批迁（提示词→画廊→组合→换脸）。
- 影响：全前端 + `templates/prompts/list.jinja2`。｜风险：`confirm()` 之类同步交互迁委托后时序不变，但 `event.stopPropagation` 语义要逐一核对。｜**M**（高危点 **S**，全量 **L**）

### U5 单一任务跟踪器 + 统一任务面
- 现状：`jobPollTimer` 单例（`job.js:16-17`）+ `_fsTimer`（`faceswap.js:633`）双轮询；3 个进度面；13 处 `trackJob` 调用。
- 目标：`jobStore` 持 `Map<jobId,{timer,last}>`，任何提交只调 `jobStore.track(jobId,type)`；渲染交给 U3 的面板组件。产品形态直接用 03 报告的"任务抽屉"，本单元只做实现承载体。
- 最小改法：先让 `fsTrack` 委托给 `trackJob`（`job_type==='faceswap'` 分支），`fsPoll` 删除；再改单例为 Map；SSE 到来时只替换 `track` 内部实现（05 报告选型），上层不动。
- 影响：`job.js/faceswap.js/generator.js/composer-*.js/history.js/gallery.js/imageViewer.js/prompt.js`。｜风险：轮询频率短期不变，删 `fsPoll` 前确认换脸面板字段齐全。｜**M**

### U6 基础 UI 原语
- 现状：toast×3、复制×9、分页×4、空状态×12、按钮反馈×4、弹窗×3 种造法。
- 目标：`ui-kit.js` 里 6 个原语：`toast(msg,type)`（含队列，避免并发覆盖）、`modal({title,body,actions})`（Esc/背景关闭/焦点归还统一）、`pager(opts)`、`empty(text,hint)`、`copy(text,btn)`、`pending(btn,text)`。
- 最小改法（无构建最稳）：一个 `window.PB` 命名空间 + IIFE 包每个文件；原语返回 DOM 而非 HTML 串；`<template>` 存静态骨架；先用新原语写新代码，再按"复制→toast→分页→空状态"顺序替换旧点（每类一次提交）。
- 影响：`utils.js/ui.js/prompt.js/faceswap.js/fragments.js/gallery.js/history.js`。｜风险：`showToast` 单元素被全站依赖，改队列必须先兼容旧签名。｜**M**

### U7 现代化路径对比（不引入打包器 vs Vite）

| 维度 | A：原生 ESM + 少量约定（推荐先做） | B：引入 Vite |
|---|---|---|
| 依赖 | 零新增，浏览器原生 `type=module` | Node + pnpm + vite + 配置 |
| 依赖顺序 | 由 import 图决定，消灭"加载顺序覆盖" | 同 A，另加打包 |
| 作用域 | 每文件模块作用域，`let`/函数不再泄漏 | 同 A |
| 内联处理器 | **必须**配 U4（模块内函数不再自动上 window），或加 `window` 桥 | 同 A（这是两种方案共同的最大成本） |
| 缓存 | 仍需手工 `?v=`（import 说明符里写死，改文件要改引用） | 内容哈希，自动 |
| 部署 | 原样拷贝 static，`启动.bat` 零变化 | 必须构建；需保留"构建失败仍能启动"回退（06 报告要求） |
| 测试 | Node 可直接 import 纯模块，可先上 `node --test` | Vitest/Playwright 更顺 |
| 迁移步数 | 6 步：①`main.js` 入口 ②kernel（utils/ui/router）转 ESM ③store ④U4 委托/桥 ⑤业务模块分 3 批转 ⑥删 htmx/Jinja | 9 步：①②③同上 ④Vite 脚手架/入口 ⑤StaticFiles 指向 dist ⑥dev 代理 ⑦CSS/资源 ⑧哈希与缓存 ⑨CI+回退 |

## 4. 明确不建议做的事

1. **绝对不要**把 `?htmx=1` 变成默认、或反向"全站改服务端渲染"——等于在无测试条件下重写一半前端，且现有 HTML 分支已落后 3 个功能。
2. 不要在 U1 之前做 U3/U6 的大迁移（03 报告同结论）：状态未收拢时抽组件，会把 4 套状态一起封装进去。
3. 不要为统一响应结构一次性改 100 个端点（01/06 已反对）；渲染器适配层自己吸收 `items/prompts/jobs` 差异。
4. 不要现在引入 Vue/React/Svelte：无测试、无构建、5 个 Tab 的存量交互无法一次性迁移。
5. 不要在 U4 完成前上 CSP `script-src 'self'`：323 处内联处理器会全站失效。
6. 不要为"消灭 innerHTML"引入运行时模板引擎（Pug/Handlebars）：多一个 vendor、多一套转义规则，收益不抵。

## 5. 与其他分报告的交叉点

1. **与 01（后端）**：01 要求"3 个 `/html` 端点最后删"，本报告 U2 的 M3/M4 已按此排序，不冲突；但 01 的"加键不删键"意味着 U3 渲染器要写适配层，别等 envelope 统一。
2. **与 03（UX）**：03 的 U1 任务抽屉 = 本报告 U5 的产品形态、03 的"统一选图器" = U3 的消费方；03 的 S3–S5 在等"渲染器定案"，本报告给定案（保留 JS），但实施仍需排在 U1 之后。
3. **与 05（任务/性能）**：SSE 选型与本报告 U5 兼容——只允许一个订阅者/一个 `jobStore`；若 05 先上 SSE，U5 的 Map 轮询可跳过，但"删 `fsPoll`"仍要做，否则同 job 双订阅。
