# Atelier 工作流接入规范（2026-11-01）

> 目标：根目录的**非特殊工作流**都遵循同一套分辨率/提示词/输出契约。
> 新工作流只要按本规范放进来，Atelier 就能直接选工作流、选比例、选分辨率、选横竖，不需要再改前端或后端。

## 1. 工作流分类

| 类型 | 判定 | 是否显示比例/画质 |
|---|---|---|
| 文生图 | 有可识别的文本编码节点 + 空 latent 节点 | 显示 9 比例 + 画质 |
| 图片处理/编辑 | 有 `LoadImage` / `LoadImageMask` / `SeedVR2VideoUpscaler` 且没有“纯空 latent”链路 | 不显示（由输入图决定） |
| 视频 | 含 `SaveVideo` / `VideoCombine` | 默认不在 Atelier 出图列表出现 |
| 工具 | 没有文本编码或没有空 latent（如 Qwen3VL 反推提示词） | 不显示 |

## 2. 统一分辨率契约

Atelier 对文生图工作流统一暴露两条输入：

- `aspect_ratio`：`1:1 / 2:3 / 3:2 / 3:4 / 4:3 / 9:16 / 16:9 / 21:9 / 9:21`
- `quality`：界面档位键 `2K / 4K / 6K / 8K / 12K` = `0.75× / 1.0× / 1.25× / 1.5× / 2.0×`；它们**只是 UI 别名**，落库与 `{quality}` 目录变量只存倍率（见本节第 11 条）。界面只显示 `倍率 · 目标 MP · 实际像素`。

后端按工作流的尺寸来源自动选择注入方式：

| 工作流写法 | 注入方式 | 说明 |
|---|---|---|
| `EmptyLatentImage` 宽高是字面量 | 直接写 `width/height` | Qwen、Flux2 |
| 宽高来自 `ResolutionSelector` | 写 `aspect_ratio` + `megapixels` | Krea2 |
| 宽高来自 `ResolutionPresetPicker` | 默认比例用原生 preset；其他比例退化成字面量宽高 | ZIT |
| 其他自定义节点 | 有 `aspect_ratio` 就用；没有就改字面量或节点 MP | 保证仍能出 8 比例 |

约定：

1. **默认比例 + 1.0× 必须保持工作流原生尺寸**，不因为接入了比例 UI 而改变默认输出。界面把这一档标成「原生」、把默认比例标成「推荐」。
2. 其他比例按 `目标像素 = 原生像素 × 倍率²` 重算宽高，并按 `multiple`（字面量 16、ResolutionSelector 默认 8）对齐。**未传 `aspect_ratio`（含空串）时用工作流 `default_ratio`**，不再退回"基准宽高 × 倍率"，否则同一档位会出现两种尺寸。
3. **MP 单位分两套**（`/api/workflows` 的 `params.mp_unit`）：
   - `mp`：字面量 / `ResolutionPresetPicker`，按 `1e6`。
   - `mip`：`ResolutionSelector` / `ImageScaleToTotalPixels`，按 `1024²`。按 `1e6` 算会偏小约 2.4%/边（例：2.16 在 9:16 下是 **1128×2008**，不是 1104×1960）。
4. **后置放大**：latent 到输出路径上有启用中的 `LatentUpscaleBy` 时，`params.post_scale` 给出累计倍率；界面标签写成 `首程 → 成品`（ZIT 为 1.7×：640×960 → 1088×1632）。被 bypass（`mode=4`）的节点不算——Krea2 里的 1.5× 就是 bypass。
5. `ResolutionSelector` 只有 8 个比例（没有 9:21）；选 9:21 时退回字面量宽高，单位仍跟随该节点（MiP）。
6. 宽高会被 clamp 到 `256..4096`。
7. 编辑/超分/视频工作流不显示比例和画质，由输入图或节点自身决定。
8. `orientation` 只为旧接口兼容保留：没传比例时用它决定"默认比例还是它的倒数比例"（`2:3 ↔ 3:2`）；新代码统一传 `aspect_ratio`。
9. 倍率是相对各工作流基准的：Krea2 2.4MP 底 × 2.0² ≈ 9.6MP，12GB 有 OOM 风险；高倍率必须按工作流实测，不能套用 Qwen 的 4MP 经验。
10. **可选档位**：工作流可在 `extra.atelier` 声明 `quality_tiers`（如 `["6K","8K","12K"]`）和 `default_quality`；`/api/workflows` 会带出这两个字段，前端只渲染允许的档位。Qwen 25 步已去掉 0.75× / 1.0×，默认 1.25×。
11. **内部键只存倍率**：数据库与 `{quality}` 目录变量统一 `0.75x…2.0x`；`2K…12K` 只是 UI 别名，写入和迁移时归一（迁移 v5）。档案里的「质量档位」按图片真实宽高反算，不显示内部键。

## 3. 文生图工作流的最低要求

1. **空 latent 节点**：`EmptyLatentImage`、`EmptySD3LatentImage` 或 `EmptyFlux2LatentImage` 之一。
2. **文本编码节点**：`CLIPTextEncode`、`TextEncodeQwenImage21`、`TextEncodeQwenImageEdit`、`TextEncodeQwenImageEditPlus` 之一，并且 `clip` 输入已连线。
3. **输出节点**：有 `SaveImage`（或类名包含 `Save` 的终端节点）。
4. **文件名前缀**：建议 `<模型>_t2i` 或 `<模型>_edit`，例如 `Qwen21_NSFW_t2i`。Atelier 提交时会再追加唯一后缀，这里只影响直接打开 ComfyUI 时的可读性。
5. **负面提示词**：只有两个文本编码节点、或编码节点自带 `negative_prompt` 字段（如 `TextEncodeQwenImage21`）时才支持；否则前端会隐藏负面输入。
6. **bypass / mute**：第二程、可选分支用 `mode=4`（bypass）或 `mode=2`（mute）。Atelier 的解析器按 ComfyUI 语义处理，不会把被 bypass 的节点原样提交。
7. **自定义节点**：必须已安装在 ComfyUI；缺失时工作流仍会出现在列表，但提交会失败。上线前用审计脚本检查。

## 4. 新增工作流自检

在 `脚本/atelier` 下运行：

```bash
python tools/audit_workflows.py
```

脚本会输出每个工作流的分类、分辨率机制、默认比例、支持比例数和输出前缀；文生图比例不完整、无法识别尺寸机制、默认比例不合法都会报 `ERROR`。

同时建议跑：

```bash
python -m pytest -q                 # 后端契约
cd frontend && npm run typecheck
cd frontend && npm test
cd frontend && npm run build
```

## 5. 前端对应关系

所有能选出图工作流的入口（提示词页、组合器、补图、批量替换弹窗）都必须同时展示 `WorkflowParams`（比例 + 画质 + 横竖），不能只给工作流下拉。图生图/换脸等由输入图决定尺寸的入口除外。

- 比例下拉：只列工作流真实支持的比例（文生图固定 9 个，含 21:9 的竖版 9:21）。
- 快捷“竖/横”按钮：只切换互为倒数的比例（`2:3 ↔ 3:2`、`3:4 ↔ 4:3`、`9:16 ↔ 16:9`、`21:9 ↔ 9:21`）；`1:1` 没有倒数对，按钮禁用。
- 画质标签：不再显示容易误解的 `2K/4K`，统一显示 `倍率 · 目标 MP · 实际像素`；1.0× 标成 `原生`，例如 `原生 1.0× · 1.01MP · 832×1216`。
- 比例和画质都按工作流分别记忆：
  - `pb.aspectRatio:<workflowPath>`
  - `pb.quality:<workflowPath>`
  - 某个工作流第一次使用时，比例用工作流默认值，画质用 1.0×。
