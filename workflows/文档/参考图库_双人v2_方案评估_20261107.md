# 参考图库 · 双人 v2 方案评估（2026-11-07）

| 项目 | 内容 |
|---|---|
| 状态 | **V2-A 已实施并验证（2026-11-07）**；V2-B（B 单脸后处理增强）暂不做 |
| 前置 | v1.5 已完成并通过 28 张分层验证（见验证文档 §13.9） |
| 目标 | 让人物 B 的身份由**指定人像图**控制，而不只靠文字 |
| 结论 | 5 图管线不是当前必需；4 图第 4 槽做 B 身份图已实测可行 |

---

## 1. 结论摘要

- **V2-A（推荐）**：复制现有 4 图工作流，把第 4 槽语义从「发型」改为「人物B参考」；A 人像 / 服装 / 姿势三槽不变。B 的脸和发型来自第 4 槽人像，B 的服装/年龄仍走文字。
  - 实测 4/4：A 身份相似度 0.776–0.806，B 身份相似度 0.733–0.770，恰好两人，无串脸。
  - 代价：**中**；不改 `FaceswapRequest`，不加第 5 个输入。
- **V2-B（可选增强）**：生成完成后，只对人物 B 做一次 `insightface + inswapper_128` 换脸。
  - 实测 B 相似度从 0.738 → **0.918**，A 保持 0.784；视觉接缝干净。
  - 代价：**中**；需要修复 onnxruntime 的 VC 运行库环境（见 §4.3）。
- **V2-C（5 图全量）**：只有同时需要「A 发型覆盖 + B 身份图」或「每个 B 变体配不同身份图」时才需要。
  - 代价：**大**；`FaceswapRequest` / 角色体系 / 5 图工作流 / UI / 测试全改。
- **V2-D（InstantID / IPAdapter）**：本机适配的是 SDXL/Flux，不是 Qwen21；要另起模型栈，不建议。

---

## 2. v2 门槛复核

v1.5 28 张结论：B 文字可稳定控制发型/服装，B 身份跨 3 seed 无漂移；因此「身份漂移」门槛未触发。  
但用户明确要「B 指定人像图」时，v2 仍有价值：它把 B 的脸从**随机生成**变成**指定参考**。

## 3. 可行性实验（V2-0，已完成）

### 3.1 方法

- 不改工作流、不改代码；用现有 4 图工作流 + `prompt_override`：
  - 图1 姿势 `psl-D026` / `psl-D030`
  - 图2 A 人像 `f71f980dde3`（短发）
  - 图3 A 服装 `SPR-0001`
  - 图4 B 身份 `f000fa12e8d`（长发标准款）
- B 服装文字：浅蓝衬衫、米色长裙、棕色乐福鞋。
- seed 20261107 / 20261108；共 4 张。

### 3.2 结果（insightface buffalo_l 余弦相似度）

| 样本 | 检测人脸 | A 相似度 | B 相似度 | 目检 |
|---|---:|---:|---:|---|
| D026 seed07 | 2 | 0.786 | 0.738 | 恰好两人；A 短发/图3衣装；B 长发/蓝衬衫/米色长裙/棕鞋；无串脸 |
| D026 seed08 | 2 | 0.776 | 0.733 | 同上；B 脸跨 seed 稳定 |
| D030 seed07 | 2 | 0.806 | 0.770 | 恰好两人；坐姿跟随；B 身份稳定 |
| D030 seed08 | 2 | 0.790 | 0.767 | 同上 |

- 判定：**4 图 B 身份槽可行**。B 相似度 0.73–0.77 已属强匹配；A 保持 0.77–0.81。
- 证据：`_tmp_pair` 下的 v2 可行性出图；`output/pair-v2-0/feasibility/`。

### 3.3 B 单脸后处理换脸（V2-B 预研）

- 用 `insightface` 检测两张脸，按「与 A 参考更像 / 与 B 参考更像」自动判定哪张是 B。
- 用 `inswapper_128.onnx` 只把 B 的脸换成 B 参考图。
- 实测（D026 seed07）：换脸前 B 0.738 → 换脸后 **0.918**；A 0.784 → 0.784（未动）。
- 目检：A 未被误换；B 的脸更接近参考；发型/服装/姿势/人数保持；接缝未见明显问题。
- 证据：`_tmp_pair/v2f-D026-s07_faceswap.jpg` 等。

### 3.4 环境门槛：onnxruntime

- 本机 `C:\Windows\System32\msvcp140.dll` / `vcruntime140.dll` 为 **14.00.24215**（过旧），
  `onnxruntime` 1.21/1.27 初始化报 `WinError 1114`；三个 Python 环境（项目 Python、ComfyUI Python、FaceFusion venv）均复现。
- 临时解法：进程内把 `ComfyUI ...\torch\lib`（VC 运行库 14.50）加到 `PATH` + `os.add_dll_directory`，
  onnxruntime 可正常加载，换脸脚本跑通；**不改系统 PATH、不覆盖 System32**。
- 生产化前必须二选一：
  1. 安装最新 **Microsoft Visual C++ 2015-2022 Redistributable (x64)**；
  2. 或在服务启动时注入随包 VC 运行库目录（与临时解法一致）。
- `ComfyUI-ReActor` / `ComfyUI-FaceSwap` 当前是 `.disabled`；启用需依赖治理，非必需。

## 4. 方案对比

| 方案 | 改动范围 | 优点 | 风险 / 限制 | 工作量 | 推荐 |
|---|---|---|---|---|---|
| **V2-A 4 图 B 身份槽** | 新 4 图工作流 1 个；`recipe_prompt` B 图像分支；`_extra_kind`；workflow catalog `extra_kind`；前端第 4 槽语义 + B 身份图选择；持久化 union；测试 | 不改 4 输入管线；B 脸/发型直接受控；A 三槽不变；空第 4 槽自动退三图 | 第 4 槽被 B 占用，**不能同时用 A 发型覆盖**；B 身份图固定整批；B 服装仍文字 | 中 | ✅ |

## 5. V2-A 推荐实施清单

### 5.1 工作流

- 复制 `图库专用_Qwen21+VNCCS_四图_可选发型_25步_单人.api.json` 为
  `图库专用_Qwen21+VNCCS_四图_可选人物B_25步_双人.api.json`。
- 只改节点 12 标题：`图4：人物B参考 (PersonB)`；不改图结构与 `image_4` 接线。
- 该工作流第 4 槽为空时仍走现有裁剪逻辑，自动退三图（v1.5 文字模式）。

### 5.2 后端

- `recipe_prompt.py`：
  - `extra_kind == "person_b"` 时新增条款：
    `• 人物B（图像参考）：图N是人物B的脸型与发型参考；人物B的脸型、五官、发型必须与图N一致；`
    `图N的服装不得用于人物B，B 的服装/年龄按文字设定；绝对不要把图N的脸或发型用于人物A。`
  - B 的文字碎片/自由文字保留，作为服装/年龄补充；A 的三槽条款逐字不变。
  - `person_b` 与 `bare` 冲突时按现有规则处理（bare 不写 B 图像条款）。
- `reference_library.py` 路由：
  - `_extra_kind` 识别 `"人物B" / "personb" / "person_b"`；
  - `RecipeRequest.extra_library` 允许 `portrait`（`_recipe_entry` 已支持本地库任意图片）；
  - 响应 `slots` 标注第 4 槽为 `person_b`。
- `comfyui.py` / workflow catalog：
  - `/api/workflows?scope=studio` 增加 `extra_kind`（hair / person_b / ""），供前端切第 4 槽语义。
- 测试：
  - prompt 单测：B 图像条款、A 隔离、单人姿势忽略；
  - API dry-run：`extra_id` 来自 portrait 库时，提示词出现「图N是人物B」；
  - workflow catalog `extra_kind` 用例。

### 5.3 前端

- 第 4 槽：
  - 当前工作流 `extra_kind=person_b` 时，标题改为「人物B参考」，选择器改为**人像库**；
  - 复用/参数化 `HairPickerModal` 为通用库选择器（hair 取背面图，portrait 取原图）；
  - 上传入口保留（上传 B 人像）。
- B 编辑器：
  - 增加「B 身份图」状态：已选则显示缩略图 + 来源；未选则提示「未选身份图时仍走文字设定」；
  - 身份图与文字碎片并存：图像管脸/发型，文字管服装/年龄。
- 持久化：
  - `StoredReferenceExtraSlot.library` 扩展为 `'hair' | 'portrait' | ''`；
  - 解析/恢复/提交体同步。
- 批量：
  - B 身份图是**整批共用**的第 4 槽，不进入组合维度；
  - A 人像 × B 变体仍按 1:1 配对；
  - 若将来需要「每个 B 变体不同身份图」，走 V2-C。

### 5.4 验收

- 功能：
  - 选中 B 工作流 + B 身份图，dry-run 提示词含 B 图像条款；A 条款不变；
  - 第 4 槽为空时退三图，仍按 v1.5 文字模式。
- 出图（建议 12 张：4 姿势 × 3 seed）：
  - 恰好两人 ≥ 11/12；A 相似度 ≥0.70；B 相似度 ≥0.65；服装完整 ≥11/12；
  - 无 A/B 串脸；B 发型与身份图一致 ≥10/12。
- 回归：
  - 后端相关 pytest、前端 typecheck / 全量 spec / build；
  - v1.5 文字模式（不选 B 身份图）不得回归。

## 6. V2-B 可选增强清单

- 触发条件：V2-A 的 B 相似度不足（<0.65）或用户要求「更像指定人像」。
- 流程：
  1. v1.5 / V2-A 出图完成；
  2. insightface 检测两张脸；
  3. 用 A/B 参考 embedding 判定 B 脸（与 B 更像、与 A 更不像）；
  4. `inswapper_128` 只换 B；可选 CodeFormer 修复；
  5. 失败（<2 张脸 / B 侧脸 / 遮挡）时保留原图并标注「未增强」。
- 工程：
  - 新增后处理服务（独立于生成队列，任务完成后异步）；
  - UI「B 身份增强」开关；输出目录与任务记录标明 `enhanced`；
  - 只对安全层启用；NSFW 不自动换脸。
- 环境：
  - 先修复 VC++ 运行库（§3.4），否则 `onnxruntime` 不可用；
  - 脚本需处理中文路径（`cv2.imdecode` / `write_bytes`，本次已验证）。
- 风险：
  - 侧脸/遮挡无法换；换脸边缘/肤色/分辨率可能失真；
  - 不能把换脸结果用于未授权素材或再分发。

## 7. V2-C 5 图全量：何时才做

满足任一条件才建议启动：

1. 用户明确需要「A 单独换发型 + B 身份图」同时存在；
2. 用户需要每个 B 变体/每个 A 人像配不同 B 身份图，且不想分批提交；
3. V2-A 的 4 图模型在多姿势下 B 身份稳定性不达标，而 5 图能解决（需先实测）。

改动会触及：`FaceswapRequest.ref4`、`MAX_INPUTS=5`、`ROLE_ORDER`、`_resolve_input_nodes`、`SLOT_ROLES` 5 槽、`loadimage_role` 新角色、前端第 5 槽、trim-check、矩阵、持久化与全量回归。工作量**大**，不建议在无明确需求时提前做。

---

## 8. 推荐决策

**先做 V2-A，保留 V2-B 作为可选增强；不启动 V2-C。**

理由：

- 实测 4/4 已证明 4 图 B 身份槽可行，B 相似度 0.73–0.77，A 保持 0.77–0.81；
- 不需要改 4 输入管线，回归面小；
- 如果 V2-A 的 B 相似度仍不够，再用 V2-B 把 B 提到 0.9+，仍然不碰 5 图；
- 只有「A 发型槽 + B 身份槽」或「按组不同 B 身份」才值得上 V2-C。

- 实现（只改前端选择层，不改后端、不分组提交）：
  - `composables/recipeModel.ts`：新增纯函数 `resolveExtraKindConflict`，按选择数组顺序判定「最新选中」（`ReferenceWorkflowSelect` 勾选时总追加到末尾）；同时存在两种 `extraKind` 时保留末尾一条、移除另一种，只有一种语义或目录未加载时不处理。
  - `composables/useReferenceRecipe.ts`：新增 `watch([workflowSelection, workflows], flush: 'sync')`，覆盖页面直接 `workflowSelection = $event` 与会话恢复两条入口；命中冲突时收敛选择并写既有 `workflowSelectionNotice`（页面已有 toast，无需改 UI）。
  - `composables/useReferenceRecipe.spec.ts`：新增 1 条单测，覆盖「先选发型再选人物B」「先选人物B再选发型」两种顺序、单语义 / 目录未加载的 no-op，以及组合层 watch 真的收敛选择并写提示。
