# prompt_browser_v4 现状调研与评估（2026-10-31）

> 调研对象：`workflows/脚本/prompt_browser_v4`
> 调研方式：4 个并行子调研（运行时实测 / 后端与数据层 / 前端架构 / UX 空间账）+ 旧前端 `git tag legacy-frontend` 对照。只读，未改任何代码、未写库。
> 口径说明：像素数据由 CSS 静态推算（1440×900，未做截图级测量）；数据量来自 127.0.0.1:8656 实时接口；命令结果为本机真实输出。

## 0 结论先行

1. **后端是健康的，问题集中在前端**：118 条 pytest 全绿、90 个端点在线、库里 334 条提示词 / 2129 个碎片 / 384 个模板，服务进程零 ERROR。
2. **"功能丢失"的本质不是删功能，而是跨页与入口断链**：跳转提示词失效、草稿恢复失效、纯磁盘换脸无法提交、6 处出图入口丢失自定义工作流内容、5 处缓存失效漏刷。
3. **组合器不是"少了个按钮"，而是换了心智模型**：旧版是 8 条并列的独立滚筒（候选与槽位同位、点击即选中打勾），新版拆成"中间碎片池 + 右侧/下方画布"，行视图首屏画布可见高度为 0。
4. **历史债务仍在结构层**：3 个页面 1000+ 行、无 URL 路由（`vue-router` 装了但 0 引用）、无共享布局壳、切页即卸载丢全部筛选/选择、组合画布刷新即丢。
5. **测试护栏位置错了**：92 条前端用例全绿、类型检查 0 错，却不覆盖 App/路由/任务/换脸/composable——所以"全绿"和"用户觉得坏了"可以同时成立。

## 2 后端与数据层

**健康事实**
- 生命周期清晰：启动维护（备份/轮转/墓碑回收）→ 单写者线程 `job-writer` → SQLite；写路径不塞事件循环。
- 数据模型已做两轮收敛：标签收敛为单 `Tag` 表 + `EntityTag` 多态关联；`GenHistory` 唯一索引改为部分唯一索引（`filename/subfolder/img_type WHERE is_deleted=0`）；`missing_since` 派生列可自愈。
- 请求链路有 `X-Request-ID` 与慢请求告警，问题可串起来。

**遗留问题（不影响"能不能用"，影响"改得动不动"）**
1. `PromptCategory/PromptTag/ImageCategory/ImageTag` 四张旧关联表仍在，与 `EntityTag` 并存（`models.py:137-201`）——双写体系还在。
2. 71%（64/90）的 200 响应没有 Pydantic schema，仍是裸 dict；前端 `apiGet` 用 `as T` 裸断言（`client.ts:28`）。
3. `/api/jobs` 曾在 22:31–22:33 因 `extra` 字段类型漂移（JSON 字符串 vs dict）连续 500 四次，重启后未复现——**数据相关、会复发**。
4. `/api/history_sync` 用 `@router.api_route(methods=["GET","POST"])`，启动即告警 duplicate operationId。
5. `/api/tags?limit=5` 参数被忽略（该路由不收 `limit`），客户端按 limit 分页会拿到全量 178 条。
6. `composer/fragments` 响应 692KB，`total_prompts` 恒为 0（兼容字段），大库继续长大会变重。
7. 日志中文在 `_pb_out.log` 里乱码（GBK/UTF-8 不一致），真正可用的日志是 `workflows/logs/app.log`。

**结论**：后端不需要"重新拆分"，需要的是补 schema、修类型漂移、清四张旧关联表。

## 6 根因

1. **核对方法论错位**：重构方用"端点差集"证明功能没丢（计划 5.5/5.6 自述），而纯前端交互不调后端，天然查不出来；计划 5.7 已承认一次事故，但只补了被点名的几项，没有建立"旧版 UI 能力清单"。
2. **前端按页搬运**：每页一个巨型组件，没有路由、没有共享壳、没有状态持久化。页面内部看起来完整，页面之间全是缝。
3. **组合器改了产品模型而不是实现**：把"8 滚筒工作台"换成了"池 + 画布"，默认还选了行视图、用 `max-height:52vh` 救火，制造双层滚动与首屏画布不可见。
4. **契约半成品**：71% 响应无 schema + 前端裸 `as T`，运行时形状错误被类型系统掩盖（`extra` 500、字面量空态都是这个底色的症状）。
5. **护栏与风险错位**：92 条测试锁的都是"已实现的局部行为"，跨页、路由、出图关键路径 0 覆盖。

## 7 评估意见（三条路线，待决策）

### A. 局部止血（工作量 S–M）
**范围**：只修 7 个真实断链（跳转 watcher、草稿恢复、换脸 canSubmit、6 处 workflow_content、5 处缓存失效、jobs `extra` 类型、任务页字面量）+ 补文件名复制；组合器恢复 8 列滚筒为默认、行视图收缩筛选；画廊侧栏可折叠、图片列宽回到 ≥200px。
**优点**：改动面小、可分批上线、后端零风险，能立刻改善体感。
**风险**：不解决无路由/切页丢状态/巨型组件，下一轮加需求仍会继续长债。
**适用**：只想尽快"用起来顺手"。

### B. 前端信息架构重做（工作量 M–L）——**推荐**
**范围**：保留后端/DB/API 契约不动。
1. 引入 `vue-router`（已装待用）：深链、返回、刷新保持、按页挂载。
2. 抽 `PageShell` + `CategoryFilter` + `BulkBar` + `Pager` + 图片 URL 工具：消灭 4 份重复，页面降到 400–600 行。
3. 每页按面板拆分：画廊（网格/侧栏/灯箱/批量）、提示词（列表/详情/出图条）、组合器（**滚筒工作台**：8 类各一条独立滚动列 + 原位选中 + 固定 📌 + 底部拼接结果，画布不再是独立 400px 栏）、任务（列表/明细）。

### C. 前端全量重写 / 按功能域重新拆分（工作量 L）
**范围**：丢弃现有 8 页结构，按功能域重新拆（画廊 / 提示词库 / 组合工作台 / 任务），重新定义布局与交互，可顺便拆成独立子页面或独立入口。
**优点**：可以彻底摆脱历史 UI 决策（如 8 页签平铺、400px 画布）。
**风险**：现有 92 条测试基本作废；后端契约仍是无 schema 裸 dict，重写会把同样的类型问题复制一遍；若核对方法仍是"端点差集"，功能回退会原样复现（5.7 已发生过一次）。
**适用**：你确认产品形态需要变（例如组合器要变成主入口、画廊要独立窗口），而不是单纯嫌现在不顺手。
