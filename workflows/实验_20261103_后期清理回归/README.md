## 1. 自动红印章检测：不可用

对 30 张真实图跑 `detect_red_seals`：

| 指标 | 结果 |
|---|---|
| 总检测框 | **2225** |
| 单图最多 | **153**（A 组纯人像，本应 0） |
| 已知 3 个印章命中 | **0 / 3** |

最差样例见 `auto_overlay_worst.jpg`：人像脸部、腿、货架、纸箱全被标红；真正的淡粉色印章反而没检出。
结论：**自动检测不作为默认入口**，只保留 API 给后续更可靠的模型/OCR 接入。

## 2. 手动框选清理：精准框有效，过大/过小有明确问题

| 案例 | 红像素 | 外区差异 | 结论 |
|---|---|---|---|
| ZIT s04 精准框 | 543 → 0（100%） | 0.001 | 印章去除，卷轴基本保留 |
| ZIT s03 精准框 | 676 → 0（100%） | 0.0005 | 同上 |
| Porn s04 精准框 | 912 → 0（100%） | 0.0006 | 同上 |
| ZIT s04 过小框 | 100 → 100（0%） | 0.0002 | **漏擦**：只擦了印章中心 |
| ZIT s04 过大框 | 557 → 0（100%） | 0.0072 | **误擦**：签名和卷轴被糊掉 |

证据图：`manual_cases_before_after.jpg`（上排前后对比）、`auto_overlay_worst.jpg`、`audit.json`。

结论：
- 精准框选能有效去掉小面积印章，且框外像素几乎不变；
- 选区过小会漏擦，过大则 OpenCV inpaint 会糊掉周围内容；
- 大面积文字/印章不应依赖 OpenCV，建议走 ComfyUI 生成式 inpaint。

## 3. 基于案例加的防呆

- 后端返回 `remaining_red`：手动清理后若选区内仍有 >20 个红色像素，提示「选区可能太小」；
- 前端选区 < 8×8 自然像素时直接拒绝；
- 选区超过图片面积 **8%** 时二次确认「可能误擦周围内容」。

## 5. 建议

1. 日常清理继续用手动框选，框紧目标；
2. 自动红章/OCR 需要换成可靠模型（如专用印章分割/OCR）再接入；
3. 大面积去除文字/印章走生成式 inpaint，OpenCV 只做小面积兜底。
